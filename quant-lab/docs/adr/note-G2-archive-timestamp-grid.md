# G2 → G0/G1/G3：公开归档时间戳的真实网格对齐情况（S29 修复的边界依据）

> 起因：十审 S29 要求"先明确离网行的隔离/拒绝规则，再按合法网格计算 present"。在把"离网即隔离"写进入口之前，必须先知道**真实归档里什么是离网的**——否则一条正确的规则会把真实数据判成脏数据。
> 结论先行：**bar 类分区可以用严格网格规则；fundingRate 不可以。**

## 1. 实测（Binance Vision 公开归档，BTCUSDT USDT-M 2024-01，湖内 silver 分区）

| 数据类型 | 行数 | 不落在网格点上的行 | 占比 |
|---|---|---|---|
| `klines` 1m | 44640 | **0** | 0% |
| `markPriceKlines` 1m | 44640 | **0** | 0% |
| `fundingRate` 8h | 93 | **15** | **16.1%** |

44640 = 31 天 × 1440，两个 bar 流都**恰好完整且全部对齐**到 60 秒网格，没有一行例外。

`fundingRate` 的 15 行偏移量只有三个取值：**+1ms、+2ms、+3ms**。相邻结算间隔因此呈现 `7.999999h / 8.0h / 8.000001h` 三种。样例：

```
2024-01-05T00:00:00.001000+00:00  interval_h=8  offset=+1ms
2024-01-07T08:00:00.001000+00:00  interval_h=8  offset=+1ms
2024-01-07T16:00:00.001000+00:00  interval_h=8  offset=+1ms
```

## 2. 对 S29 修复的三条约束

1. **`check_bars` 可以采用严格网格规则**（时间戳必须落在 `[cal_from, cal_to)` 的合法网格点上，否则隔离）。真实归档里 bar 类零离网，该规则不会误伤任何现有数据；它挡的是入湖异常与合成非法输入，属纯增益。
2. **该规则不得套用到 `fundingRate`**。结算时刻在真实归档里带毫秒级抖动，严格网格规则会把 16% 的真实结算行判成脏数据，进而把资金费账务整段判为缺证据。`partition_check.check_funding` 现有的 **60 秒容差**正是为此存在，是对的，不要"顺手统一"掉。
3. **因此 S34（funding 8h 网格自成一份公式）不是同族遗漏，是不同的规则。** 它与 `grid_points_between` 的差别不是实现重复，而是**语义不同**：bar 网格是精确的，funding 网格是带容差的。A24 的树级 lint 若把 funding 的时长除法一并禁掉，会逼出一个错误的归一。lint 必须为 funding 留显式例外，并在例外处注明本文的实测依据——**例外要有证据，不是有豁免**。

## 3. 抖动的量级与容差的量级差 4 个数量级

实测最大偏移 3ms，现有容差 60s，比值 2 万倍。容差档位远大于观测抖动，说明它不是为了掩盖一个已知误差而调出来的数，而是宽松的安全边界。若未来要收紧，本文给出可用的实测上界：**单品种单月的观测抖动 ≤ 3ms**。收紧前需在更多品种/期间上复测，因为 3ms 是一个月一个品种的样本上界，不是归档的保证。

## 4. 限制

单品种（BTCUSDT）、单月（2024-01）、两个 bar 流 + 一个 funding 流。bar 类"零离网"的结论在这个样本上是确定的（逐行核对 89280 行，非抽样）；推广到其他品种与期间前，建议在 M-03 入湖时把"离网行计数"作为 manifest 字段常态记录，让这条性质变成被持续验证的，而不是一次性测过的。
