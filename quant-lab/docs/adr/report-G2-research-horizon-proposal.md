# G2 → G0/G3：`research_horizon_s` 取值提案（契约 §5.14 B12）

> G0 要求：依据右删失率随观察窗变化的曲线提值，不由任何人拍脑袋。该取值直接决定任何 θ 声明依赖的删失率，属 `G-STAT-CLAIM` 实质内容。

## 1. 方法

- **数据**：Binance Vision 公开归档 BTCUSDT USDT-M 2024-01（湖内 `klines` / `markPriceKlines` / `fundingRate` 分区，体检 `check_status=ok`、`missing=0`）。1m 重采样为 15m（`open=first, high=max, low=min, close=last, volume=sum`）。
- **合成计划**：47 个 episode，`t_dec` 自 2024-01-01 12:00 起每 12h 一个，且保证 `t_dec + 7d` 仍在数据内；多空交替；`market_ref` 入场，SL 1.5%、TP 3%（R:R≈2），`risk_budget` 定量，`entry_ttl=1h`，`max_holding=None`。政策 `base-v1`（真实费率/滑点档、`participation=0.1`）。
- **观察窗**：同一批 episode 分别以 4h / 12h / 1d / 3d / 7d 重跑（`horizon_source=caller`），统计 `outcome_kind`。
- 每个 episode 额外供给 `t_dec` 前 2h 历史 bar——`t_dec` 落在 00:00/08:00/16:00 时，资金费结算需要一根**已闭合** mark 才能取结算价（否则按 §S02 正确判 `MARK_STALE`）。这是实验必要条件，不是内核缺陷。

## 2. 结果

| 观察窗 | n | `right_censored` | `unevaluable` | `n_evaluated` | 右删失率 |
|---|---|---|---|---|---|
| 4h | 47 | 37 | 0 | 10 | **78.7%** |
| 12h | 47 | 23 | 0 | 24 | **48.9%** |
| 1d | 47 | 12 | 0 | 35 | **25.5%** |
| 3d | 47 | 2 | 0 | 45 | **4.3%** |
| 7d | 47 | 0 | 0 | 47 | **0.0%** |

终态分布（节选）：4h → stopped 8 / tp_hit 2；12h → stopped 18 / tp_hit 6；7d → stopped 31 / tp_hit 16。

## 3. 提案：`research_horizon_s = 259200`（3 天），标**待定**

理由，以及为什么不取两端：

- **不取 4h / 12h**：删失样本被 G3 **排除出 θ 的分母**（不记 0）。4h 档排除 78.7%，θ 实际只描述"4 小时内就走完的信号"——这不是原问题的 estimand，而是一个偏向高波动、快速兑现样本的子总体。这正是 G0 说的"少数已成熟样本上的 θ"，是幸存偏差的一种。12h 档仍排除近半，同病。
- **不取 7d**：删失率降到 0 的代价是标签窗口远超这类信号的实际持有意图（SL 1.5% / TP 3% 的括号本就设计为日内到数日兑现）。窗口越长，标签里混入的越是与信号无关的后续行情；同时机会区间 `t1` 重叠增加，purge/embargo 会削掉更多训练样本，等于用统计效率换一个已经很低的删失率。
- **取 3d**：删失率 4.3%（45/47 得到成熟标签），既避开子总体偏移，又不把标签拉长到与信号意图脱节。从 3d 到 7d 只换来 2 个样本，边际收益已很小。

## 4. 必须随提案一起记住的限制（不要把本表当结论用）

1. **单品种、单月、单一括号**。2024-01 的 BTC 是上行趋势月；SL/TP 距离固定 1.5%/3% 是我编的，不是 G1 真实计划的分布。**真实 `order_plan` 的括号宽度决定这条曲线的形状**——括号越宽，同一观察窗下删失率越高。P2 用真实 gold 计划重算前，本值只能当占位。
2. **15m 重采样**会轻微低估同 bar 内的触发（更粗的路径），倾向于**高估**删失率；因此真实 1m 下的删失率应略低于本表。
3. 本实验用 `path_scenario=primary` 单一路径，未跑 adverse/favorable；三档路径会改变 stopped/tp_hit 的比例，但对"是否在窗口内走完"影响较小。
4. 当前实现按 G0 指示暂取 `research_horizon_s = max_horizon_s`（14d，保持既有行为）并标待定；**若采纳本提案改为 3d，是一次 policy 内容变更**，会改所有 `policy_hash` 与 `trace_hash`，需按 §5.5 B4 走版本登记。

## 5. 给 G3 的一条

删失率不是单调"越低越好"：它与 `t1` 重叠、purge/embargo 损耗、以及每单位时间的独立机会数此消彼长。选窗口时建议同时看**同一批数据下的 `n_evaluated` 与折内有效簇数**，而不是只看删失率。若 G3 有现成的折生成器，可用本脚本的 47 个 episode 直接跑一遍两端（3d vs 7d）的簇数对比，再定稿。

复现脚本（只读公开归档，不写湖）：会话 scratchpad `censor_curve.py`；如需固化进仓库请告知，我按 `tests/market/` 或 `docs/adr/` 归档。

## 6. 用真实括号分布重算（G0 R29 要求；曲线 v2）

G0 指出我的 1.5%/3% 是自编括号，并实测真实计划中位 TP 5.83%、SL 1.70%。我直接读了 G1 gold（`episode__fixture-v1@0c51102b`）取**真实括号形状**重算，而不只是套两个中位数：

- 67 条完整括号：SL 距离中位 **1.75%**（P10 1.12 / P90 3.31）；最远 TP 距离中位 **5.71%**（P25 3.26 / P75 6.81 / P90 12.58 / 最大 25.75）；首档 TP 中位 3.11%。
- **档数分布：1 档 25 条、2 档 2 条、3 档 40 条**——多数是三档止盈梯，分数留空即 policy 等分，**要全平必须打满三档**。这一点比中位数更能解释删失：我 v1 的单档假设让仓位一次就走完。
- 多空 57:10（真实计划强烈偏多），我 v1 用的是 50:50。

方法同 §1，改为：24 个 t_dec（每 24h）× 67 条真实括号（按相对位置缩放到当日 BTC 价，保留原档数与方向）= 每档 1608 个 episode。

### 修正提案：`research_horizon_s = 5 天`（432000）

用与 v1 同一条标准（删失率低到不让 θ 漂移成子总体的 estimand，同时不为边际样本赔上统计效率）：

- 3d 的 15.3% 太高：被排除的 15% 恰是走得慢、括号宽的那批，θ 会偏向快速兑现样本——正是当初否掉 4h/12h 的同一个理由，只是程度轻些。
- 5d 降到 **6.0%**，与 v1 里我认为可接受的 4.3% 同量级；再延到 7d 只从 6.0% 降到 3.4%，多花两天窗口换 42 个样本，`t1` 重叠与 purge 损耗的代价已不划算。
- 2 档梯在 5d 仍有 12% 删失（样本仅 2 条，不足以据此调值，标出待真实数据扩样后复核）。

仍为**占位**：单品种（BTCUSDT）、单月（2024-01 上行月）、15m 重采样（倾向高估删失）、primary 单路径。P2 真实数据阶段须按当时的品种与期间重算。改值走 B4 版本登记。

## 7. G0 裁定 B20（2026-09-11）：占位解除，取值定稿为 5 天

**占位状态解除。** 占位的依据是"待最小有效簇数约束确立"，而该约束的论证前提（"删失率与有效簇数反向、口径 B 以有效样本为代价"）已被 B20 撤销——见 `report-G2-partial-exit-estimand.md` §5.2：按 max-t 真正的重采样单位（`maxt.calendar_blocks` 的 `n_nonempty`），口径 A 与 B 的有效样本数在各观察窗上相同或 B 更优，那个反向关系不存在。

### 7.1 解除占位**不需要** B4 版本 bump

`research_horizon_s` 的**取值自 B16 起就是 432000（5 天），本次没有变**。变的只是它的**决策状态**：从"暂定、待约束确立"变为"定稿"。

- 占位标注（`policy_hashes.json` 的 `_note` / `_placeholder_fields`）是**下划线前缀的元数据**，`load_policy_registry()` 明确过滤掉它们，不参与版本查找；
- `content_hash` 由 `ExecutionPolicy.model_dump()` 算出，**不读这个 JSON 文件的元数据**。

因此解除占位**不改任何 `content_hash`、不改任何 `trace_hash`**，B4 要求的 bump 条件（内容变更）未触发。原 `_note` 里"最终值定稿时按 B4 bump 到 v2"那句写于"最终值可能不同于 5d"的假设下，该假设已不成立，据此不 bump。

### 7.2 一个必须说明的后果

既然内容未变、哈希未变，**占位期产出的结果与定稿后产出的结果在哈希上不可区分**。这是正确的——经济内容确实没变，占位是关于**信心**的标注，不是关于**内容**的。若将来需要回答"某个结果是在占位期还是定稿后产出的"，答案只能来自看板与 changeLog 的时间线，**不能来自 `trace_hash`**，也不应为此制造一次没有内容变化的 bump。

### 7.3 随裁定新增的 P2 前置（`G-STAT-CLAIM` 实质内容）

基于 5d 观察窗的 θ 声明，**每折日历长度须满足 Q × 5 天**（Q = 所需非空日历块数；Q=20 → 100 天，Q=30 → 150 天）。不满足时只能作**描述性报告**，不得作 θ 声明。

理由是算术不是统计：块自举要求 `block_len ≥ research_horizon_s + purge/embargo`，故块数上限 = 日历长度 ÷ block_len。**2024-01 单月在 5d 下只有 5 块，任何合理下限都过不了——这是数据量结论，不是取值结论。** 把后者误报成前者，会让人去调一个本来正确的参数。

下限声明的形式要求（B20 采纳）：**下限必须与 `block_len` 成对声明**（只写块数不写块长，同一个数字可以对应任意强度），口径须写成"`maxt.calendar_blocks` 的 `n_nonempty`"这样的逐字实现对照而非口径名称，并同时钉住 `cross`（跨块簇占比）与 `max_span` 两个诊断量。
