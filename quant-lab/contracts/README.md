# quant-lab 接口契约总纲 (Contracts)

> 本文件是 quant-lab 的「接缝真相」。所有窗口以它对齐，**由 GOAL-0 维护**，其余窗口只读，发现不一致就在 `taskList.json` 里提 blocker。路线依据是合并稿 `docs/plans/2026-09-11-quant-scale-up-merged-plan.md`（下称"合并稿"），契约与合并稿冲突时以合并稿为准并由 G0 改契约。

## 0. 项目一句话

`quant-lab`：把五个 Telegram 信号频道 2024 年起的全历史整理成可评估的交易 episode，在自有表达式引擎与事件级评估器上做可复算的研究；产出只进 `research_only`，任何上线、影子、RESUME 都要用户另行明示。质量底线：**无前视（三时钟 as-of）、无幸存者偏差掩盖（隔离不删除、损耗可数）、零生产凭据。**

## 2. 看板协议

**铁律：**
1. 只用 `python3 scripts/task.py` 改看板，不手改 JSON。
2. 只动自己模块的 `modules.<module>` 子树；`contracts` / `integration` 只有 G0 能写。
3. 完成一个任务或状态变化立即上报。被卡 → `block`；对方就绪 → 自己 `unblock`。
4. **自报 done 不算完成**：G0 以实跑 `verify` 命令且产出非空为准。
5. **verify 命令的 collect 检查（2026-09-11 实测修订）**：pytest 9.1.1 输出是 `N tests collected`，**不是** `collected N items`。看板里 D-01 / M-01 / R-01 写的 `--co 2>&1 | grep -E 'collected [1-9]'` 永远匹配不上（实测 grep 退出码 1），整条 `&&` 链必失败。各窗口自行把本模块该行改成规范写法：
```bash
.venv-gN/bin/python -m pytest tests/<mod> --co -q 2>&1 | grep -Eq '[1-9][0-9]* tests? collected'
```
6. 顺带：`grep -q` 比 `grep -E` 更适合放进 `&&` 链（不污染输出）；任何 verify 都必须在前台实跑核对过 grep 模式，禁止照抄未验证的模式。

```bash
python3 scripts/task.py show
python3 scripts/task.py claim data D-03
python3 scripts/task.py report data --status in_progress --progress 0.4 --note "..."
python3 scripts/task.py done data D-03
python3 scripts/task.py block research --on "契约: feature-snapshot §3 缺 weight 列"
```

## 3. 环境仲裁（防多窗口互相拆台）

1. `.python-version` 钉 3.12；`requirements/*.txt` 钉版本；改版本走 G0 契约变更。
2. **每窗口隔离 venv**：`.venv-g1` / `.venv-g2` / `.venv-g3` / `.venv-g0`，绝不共用 `.venv`，绝不重建别人的 venv。
3. 镜像与重试在 `uv.toml`；安装失败换镜像重试，不换环境。
3b. **本机没有 `python` 命令，只有 `python3`**：看板一律 `python3 scripts/task.py ...`；跑模块代码一律用本窗口 venv 的解释器（`.venv-gN/bin/python`）。目标文件里写成 `python scripts/task.py` 的地方按此替换。
4. 长驻服务（Label Studio、DuckDB 查询服务）用 `nohup` 起，端口固定：Label Studio 8081、任何 dev server 8090+，不抢生产端口。
5. 研究湖 `data/` 是共享目录：**bronze 只读带 sha256，只有 G1（telegram）和 G2（market）各写自己的分区**，G3 只读。

   **5.1 分区归属（2026-09-11 OR-02 R5 加严，规范性）**——每个窗口**只准**删改自己名下的路径：

   | 窗口 | 可写/可删路径 | 其余路径 |
   |---|---|---|
   | G1 data | `data/lake/telegram/**`、`data/quarantine/telegram.parquet` | 只读 |
   | G2 market | `data/lake/market/**`、`data/quarantine/market.parquet` | 只读 |
   | G3 research | `data/lockbox/**`（尝试账本）、`data/cache/research/**`（自建）；`data/lake/**` 一律**只读** | 只读 |
   | G0 orchestrator | 不写 `data/`（集成冒烟用 `tmp_path` 或 `data/tmp/e2e-*`） | 只读 |

   **5.2 禁止对研究湖根做删除。** 任何窗口的源码、脚本、任务 `verify`、临时命令中**不得**出现对 `data/`、`data/lake/`、`data/quarantine/`（目录本身）的 `rm -rf` / 递归删除 / 重建。清理只能精确到本窗口分区（例：`rm -rf data/lake/telegram data/quarantine/telegram.parquet`），且必须是**幂等重建**流程的一部分。

   **5.3 违规判定**：删改他人分区 = **契约漂移，G0 一律判 `fail`**，该窗口当轮里程碑不得推进，并须(a) 看板 note 立案，(b) 协助被害窗口重建，(c) 把致害命令从源码与 `verify` 中移除后由 G0 复核命令全文。

   **5.4 判例**：2026-09-11 04:38 / 04:44 G1 两次 `rm -rf data` 清空 G2 真实行情湖（`data/lake/market`）。已由 G1 立案、致歉、整改（D-07 `verify` 收敛为 telegram 子树），G2 重新入湖。本条即由该事故生成。

   **5.5 G0 复核义务**：任何含删除动作的 `verify`，G0 在实跑前必须先打印其全文并确认删除范围不触及 §5.2 的根路径；不满足即**不跑并判 fail**。

## 9. 裁定 A21：审计记录必须入库，报告不得先删旧终裁再写新终裁（G0 OR-02 R38，changeLog #43）

### 9.1 `docs/adr/` 必须纳入版本控制

**事实**：截至 R38，`quant-lab/docs/adr/` 的 **21 份文件、772K** 从未进入 git——三份引擎 ADR、G1/G2/G3 的全部审查轮次、闭合表、观察窗与 estimand 提案，全部只存在于工作区磁盘上。它们**未被 `.gitignore` 排除**，只是从未 `add`。

**这是 G0 的疏漏**：每轮都在提交 `contracts/` 与 `taskList.json`，却从未提交它们所**援引的证据**——裁定被版本化了，裁定所依据的材料没有。已于 R38 一次性入库（commit `c14eee7`）。

**裁定**：`docs/adr/**` 与 `contracts/**`、`taskList.json` 同级，属**必须入库**的审计记录。任何窗口产出新的 ADR、审查报告或提案后，由 G0 在当轮评审中提交。

### 9.2 报告不得"先删旧终裁、再写新终裁"

**风险在本轮变成具体的**：九审正在原地重写 `review-G2-P1.md`，**已删除八审终裁行而新终裁尚未写入**，文件当时处于"零终裁"状态。若该轮悬死（前若干轮确实多次悬死），八审结论将**永久丢失**，且当时无 git 历史可恢复。

**裁定**：
1. 审查报告**只追加、不覆盖历史轮次的判定文字**（G2 此前"历史轮次原文保留"的做法是对的，应保持）；
2. 新一轮的终裁行**追加在文末**，旧轮终裁行**原样保留**并以轮次名区分；review 类 verify 按 §9.9 A7 取**最后一条**，行为不受影响；
3. 确需整体重写（如 G2 曾把正文外移为 `rounds-1-2.md` 快照）时，**必须先提交当前版本入库**，再重写。

**一般原则**：**在覆盖一份记录之前，先让它可恢复。** 这与 §9.10.2 的"published 不可原地变更"、§9.8 A6 的"改门须同时发布制品"是同一条纪律在文档上的体现——G1 曾因同名原地改写 parquet 触发判例 2，本条防的是同一件事发生在审计记录上。


## 10. 裁定 A22：无法区分成功与失败的检查 + 入库到正确状态（G0 OR-02 R39，changeLog #44）

### 10.1 更正 G0 在 R38 的说法

R38 称 `docs/adr/` "已一次性入库（`c14eee7`）"，语气上像是问题已解决。**G2 更正属实，G0 实测确认**：`git show c14eee7:quant-lab/docs/adr/review-G2-P1.md` 为 **318 行、零终裁行**——入库的正是"删旧未写新"那个窗口，**该动作把损坏状态固化了**。

**教训**：**"入库"与"入库到正确状态"是两件事。** 提交一份正在被改写的文件，得到的是一个损坏快照的永久记录，不是一份保险。

### 10.2 但八审终裁并未丢失 —— 看板是有效的第二记录

G0 实测：`git show 323c9cb:quant-lab/taskList.json` 的 `modules.market.review.note` 逐字记载 **"八审**实际终裁为 fail**（319 行，未完成标记 0，G0 已复核）"**。该记录与损坏的报告文件相互独立，且已入 git。

**由此确立一条规范（此前只是 G0 的习惯）**：G0 的评审 note **必须逐字记录关键结论本身**（终裁文字、行数、计数、关键数值），**不得只写"见某文件"**。理由本轮已被验证：**引用会随被引用物一起损坏，抄录不会。** 看板与报告是两条独立链路，任一条损坏时另一条仍可复原事实。

### 10.3 一个无法区分成功与失败的检查，比没有检查更坏（采纳 G2 的自陈，列为规范）

G2 自陈：其突变自证脚本用"还原后 `rc` 是否为 1"作为还原检查，而 **"文件正确还原（终裁 fail）"与"文件被毁（找不到终裁行）"都得 `rc=1`**——该检查**在原理上无法区分成功与失败**，于是脚本在文件已被破坏时报告"已还原 ✓"。八审终裁行即在此丢失。已改为内容 SHA256 比对。

**裁定：凡"还原/回滚/恢复/同步完成"类检查，必须使用能区分目标状态与损坏状态的判据**（内容哈希、逐字比对、行数+关键行联合断言），**禁止使用被检查对象的退出码或存在性**作为还原成功的证据。

**归入同族并给出其位置**：本族此前各例是"用看似合理的值悄悄替换真实值"（兜底贴标签、`or` 吞假值、有损转换、未知当 1）；本例是它在**验证层**的对应物——**一个看起来在把关、实际无法失败的检查**。危害更隐蔽：前者骗的是数据，后者骗的是"我们已经检查过了"这一信念。与 §5.16 B14 的定级一致，属最重档。

### 10.4 落实

1. **每轮审查落盘后立即提交**，不攒（采纳 G2 建议）。攒着提交会让"提交时刻恰好落在重写窗口内"的概率随攒的轮数上升。

## 11. 裁定 A23：源码文本断言的两种用法必须分开（G0 OR-02 R40，changeLog #45）

G2 按 §10 A22 自查验证层，报出 6 处 `inspect.getsource` 文本断言。G0 逐条核实（`tests/market/test_constants_effective.py:113/114/123`、`test_outcome_kind.py:252/253/264`），**结论比"全部替换"更细**：这 6 处分属两类，只有一类无效。

### 11.1 正向委派断言 —— 无效，必须改为行为证明

形如 `assert "first_grid_point" in getsource(KernelA._first_bar_gap)`、`assert "derived_t_start" in src`、`assert "resolved_t_start" in src`。

**文本出现不等于该路径真的被走。** 调用被条件短路、调用了却丢弃结果、调用在死分支里——断言照样绿。**它在原理上无法因"委派失效"而失败**，正是 A22 定义的形态。

**裁定**：证明"确实委派给单一来源"必须用**行为证据**——把单一来源函数 monkeypatch 成哨兵值，断言调用方的**可观察输出随之改变**。改变则委派成立；不变则委派是假的。

### 11.2 负向模式禁令 —— 合法，但须正名并降格

形如 `assert 'multiplier"] or "1"' not in src`、`assert "(req.t_start or req.t_dec)" not in src`。

**这类不在禁止之列，且有行为测试替代不了的价值**：它防的是**已删除的错误写法被重新引入**，而重新引入处若当前不可达（如 §5.16 B14 的 `multiplier`：两个生产者都硬写 `"1"`，缺陷今日摸不到），行为测试**不会变红**，只有文本禁令会。

**裁定**：保留，但须满足两条——
1. **正名为 lint**：测试名与注释明确其为"禁止模式复现"，不得表述为行为证据；
2. **不得作为某项行为主张的唯一证据**：凡声称"某行为已正确"的断言，必须另有行为测试；文本禁令只作防回归的第二道。

### 11.3 附带确立一条审查表述规范

八审曾写"现有 `test_s26` **仅查源码**，本轮用实际调用**补足行为证据**"。该表述被 G2 归档为"补充证据（可选）"，而其真实含义是"**你那条断言无法失败，该门当前无效**"。G2 自陈这是其对同一条反馈的**第二次误读**。

**裁定**：审查方发现某断言在原理上无法失败时，**必须以"断言无法失败 / 该门无效"表述并标为阻断项**，不得写成"证据不足 / 建议补充"。两种措辞在接收端的分流完全不同：前者进必修，后者进待办。**一个无效的门与一个缺失的门同等严重，措辞不应让它看起来更轻。**

## 13. 裁定 A25：裁定文件不得冒充审查轮次；不同性质的证据须各走各的 verify 子句（G0 OR-02 R43，changeLog #47）

### 13.1 命名：裁定是裁定，审查是审查

`review-G1-P1-r2..r5` 由**独立审查方**出具，`分类闭合判定`由 **G0** 出具——二者证据性质不同：前者是外部独立核验，后者是仲裁方依标准作出的判断。若把后者命名为 `r6`，任何人顺序读 `r2..r6` 都会认为这是第六轮独立审查。**文件名不得使证据来源发生误认。**

### 13.2 verify 形式：不同性质的证据不得共用一个通配

G1 现行 D-10 verify 以 `ls docs/adr/review-G1-P1-r*.md | sort -n | tail -1` 取最新轮次后判读终裁行。**把 `分类` 加进前缀白名单而仍用该通配，等于让一份非审查文件靠文件名进入审查轮次序列**——这正是 §13.1 要防的误认，只不过发生在机器判读侧。

**裁定**：D-10 verify 改为**显式析取**，两个子句各读各的文件：

```bash
# 子句 A：最新一轮独立审查的正向终裁
f=$(ls docs/adr/review-G1-P1-r*.md 2>/dev/null | sed -E 's/.*-r([0-9]+)\.md/\1 &/' | sort -n | tail -1 | cut -d' ' -f2)

|| \
# 子句 B：G0 分类闭合裁定（仅此一个具名文件，不通配）
{ test -f docs/adr/ruling-G0-D10-classification-closure.md \
  && tail -5 docs/adr/ruling-G0-D10-classification-closure.md | grep -Eq '^分类终裁[：:] *\*{0,2}pass'; }
```

**一般规则**：**verify 的每个子句只读一类证据，且以具名路径而非通配指向它。** 通配的作用是"自动跟上新一轮同类证据"，把异类证据塞进同一通配，就把这个便利变成了漏洞。

**准。** 理由采纳 G2 的论证：**A24 现有两道都是语法机制，其防线边界等于"枚举到的写法集合"，该边界原则上不可能封闭**——每补一个节点类型只是把它往后推一格。升级路径已是：人工横扫（三次失败）→ 语法门（现被常规写法穿过）。**下一格不该继续加语法节点，而该换一层。**

| 机制 | 捕获 | 不可替代之处 |
|---|---|---|
| 树级负向禁令（语法） | **重复** | 在**不可达区域**仍有效（行为测试跑不到的地方，如 §5.16 B14 的 `multiplier`） |
| 调用点登记（结构） | **绕过** | 捕获"登记的调用方不再调用" |
| **性质差分（语义）** | **偏离** | **与写法无关**，不随节点类型枚举而失效 |

**G2 的判断记为规则依据**：**我们真正怕的是偏离；重复之所以危险，正因为它使偏离成为可能。** S32/S33 当时"当前等价"，靠的是运气。

**同时记明差分测试的边界**：它只能在**生成器实际走到的路径上**发现偏离；因此**不取代**语法禁令在不可达区域的作用。三道并行，缺一不可。

#### 4. 裁定：`partition_check` 那处改为委派，不登记为例外

依 §5.20 B18 第 2 节确立的标准——**例外要有证据**：豁免须附**真实数据上的实测**，证明统一规则会误判真实行。`fundingRate` 拿到了（93 行中 15 行离网、16.1%），**`partition_check` 这一处没有任何此类证据**，且其形态与 S32/S33 同族（那两条均已判归一）。

**裁定：改为委派 `grid_points_between` / `first_grid_point`，不得以"当前等价"为由保留。** 若后续实测表明委派会误判真实分区，按 B18 §2 以证据申请例外，G0 另裁。

#### 5. 附记：防线升级不应被视为终局

三次人工横扫失败 → 语法门 → 语义差分，**每一层都是在上一层被穿过之后才采纳的**。本节不宣称第三层不可穿过；它的意义在于**把绕过的代价从"换一种写法"提高到"写出一个真正不同的答案"**。后者会被差分测试抓住，而前者不会。**若将来第三层也被穿过，正确的反应仍是换层，不是补枚举。**


## 16. 裁定 A29：突变取证须进程隔离；测试不得写生产文件；空登记优于假登记（G0 OR-02 R54，changeLog #55）

#### 1. 确认 G2 对"跨窗口登记为空集"的裁定 —— 准，且理由可推广

G2 裁定：`research/` 目前无任何 `force_close_net_R` 调用，**本轮跨窗口登记为空集，不得预登记尚不存在的 G3 调用方**。

**准。** 其理由——**"一份声称存在而实际不存在的调用方，登记本身就是假的"**——直指 §12 A24 的立身之本：**登记的全部价值在于它如实反映树**。预登记一个不存在的条目不只是"提前写"，它会让"登记集合 == 实际调用方集合"这条断言**因错误的原因而通过**，于是那道门在最该说话的时候沉默。**宁可空集并明写"G3 尚未接入"，不可为凑形式写假条目。**

G2 同时要求在函数与测试模块 docstring 各写一句边界声明：**夹具只证明函数行为与 A24 机制对本函数生效，不证明 G3 确实调用而非自算**。该边界由承包方主动提出、G2 原样采纳，G0 认可——**"测试夹具证据不能冒充真实消费方的证据"**，这与 §11 A23 禁止正向委派断言是同一条。

#### 2. 突变取证必须进程隔离与真实写盘（A22 在审查方工具链上的复发）

G2 报告并经其子进程复核确认：审查方 P11G/P11TTL 的取证用 `patch(pathlib.Path.read_text)` 驱动测试，**两次 `pytest.main` 跑在同一进程**，pytest **缓存了在 patch 下完成的收集结果**；而 `test_single_source.py` 现有按树内容参数化的用例，于是 patch 下收到 14 条、还原后仍是 14 条，**`RESTORED` 判读恒定跟随第一次**。十一审当时报 `RESTORED 0`，是因为收集恰好稳定——**方法缺陷一直在，只是没显形**。

**这是 §10 A22 的原样复发，只不过这次发生在审查方的工具链里**：一个**在原理上无法区分成功与失败**的还原检查。A22 当时是针对窗口立的，**现明确其同样约束审查方**。

**裁定**：
1. 突变取证（窗口自证与审查方取证**同等适用**）必须**真实写盘 + 子进程隔离**，禁止以同进程 `patch` + 重复 `pytest.main` 充当基线/还原比对；
2. 还原判读**以内容 SHA256 为准**（A22 已立），**且必须在新进程中重跑**；
3. 该要求写进此后每份 review 任务书。

**追溯口径**：此前以该方法得出的 **RED（检出）结论不受影响**（那来自真实 patch 下的运行），但其 **`RESTORED` 结论不可单独采信**；本项目实际已由 G2 事后独立比对 sha256 覆盖，**不要求重做历史轮次**。

#### 3. 测试不得写生产文件

`tests/market/test_outcome_kind.py:352-370` 读取并**写入真实的 `src/quant_lab/market/policy_hashes.json`**（写 probe 政策，`finally` 还原）。G0 读源确认属实。

**问题不在"正常路径能还原"**，而在：
- **`finally` 挡不住 `SIGKILL`**；
- **并发跑测试会竞争该文件**——G2 早期数次复核结果互相矛盾（293 passed / 9 failed / 4 failed），根因即此竞争窗口叠加承包方在报 completed 之后仍在写文件。

**裁定**：测试**不得读写 `src/` 下的生产文件**；需要变体登记表时用 `tmp_path` 或依赖注入。要求实跑证明**全套测试前后该文件 mtime 不变**。

#### 4. 记 G2 的一条纪律，G0 同样适用

> **"job status=completed" 不等于"文件已落盘完毕"。**

G2 实测其承包方报 completed 后**仍在写文件**（mtime 就在其测量前两秒）。G0 在本会话中亦多次因此把写入中间态误读为缺陷（R32/R34/R45 等）。**裁定：判定任何模块状态前，须先核关键路径文件的 mtime 距今间隔；处于写入窗口内的一律记"不判"并说明理由，不得记为缺陷。** 这不是宽容，而是**把"测量时刻"当作证据的一部分**——不记录测量时刻的结论，在移动靶上没有意义。


## 17. 裁定 A30：A29(4) 改为双向义务；方法缺陷不自动污染已独立复现的结论（G0 OR-02 R55，changeLog #56）

### 17.1 A29(4) 的归因写法与义务范围，按 G2 所请改为双向

§16 A29 第 4 节把"移动靶误读"记成 G0 单方面失误，并只约束下游（判定方核 mtime）。**G2 反对该记法，理由成立，予以采纳并修订。**

**G2 的论证**：**记法本身会决定下次谁去查什么。** 记成"G0 三次误判"，改进方向会落在"G0 要更仔细读"；而 §12 A24 第 2 节已判过这条路走不通——**依赖人去记得的机制已经失效**。记成"上游在移动靶上给了结论"，方向才落在能自动生效的那条。

**事实层面 G0 复核并确认**：R45 那次 G0 写"门本身在真实输入上不生效"，是在 G2 报告修复完成之后作出的，**而 G2 当时报的状态其文件仍在落盘中**；B18 的虚构取舍，其对照数据由 G2 计算并提交。**G0 读到的是上游给的结论，不止是自己误读原始材料。**

**修订后的 A29(4)（双向义务，替代原单向表述）**：

1. **上游义务**：报告任何"已完成 / 已闭合 / 已修复"状态时，**必须附测量时刻与关键路径文件的 mtime**；处于写入窗口内的，**必须自行写明"不判"**，不得给出状态结论。
2. **下游义务**：判定前**必须自核** mtime 距今间隔；处于写入窗口内一律记"不判"并说明理由。
3. **两条缺一不可**：**只约束下游时，这道门在最该说话的时候同样会沉默——因为它信任了一份没有时间戳的上游结论。** 这与 §5.17 B15 第 2 条（一支查了另一支没查）是同一形态，只不过发生在协作接缝而非代码分支上。

### 17.2 方法缺陷不自动污染已独立复现的结论

§16 A29 第 2 节指出审查方取证方法的 `RESTORED` 判读不可信。**须同时记明其边界，否则后来者会由"取证方法有缺陷"连带怀疑结论**：

- **受污染的只有 `RESTORED`**；`RED`（检出）来自**真实 patch 下的运行**，patch 确实生效、测试确实红，**与进程复用无关**。
- **十一审两条阻断（S40/S41）已由 G2 以真实写盘 + 子进程隔离独立复现**：S40 注入 2 failed、S41 注入 1 failed，还原后各 26 passed、sha256 一致。**故十一审的阻断判定本身站得住，不因方法缺陷而动摇。**

**一般规则**：发现某取证方法有缺陷时，**须逐项划清该缺陷实际影响哪些结论**，并对未受影响者明确背书。**笼统地让方法缺陷"传染"全部结论，与笼统地无视它，同样是不做区分。**

### 17.3 附记 G2 对 §15 A28 的一句概括

> **换层不免除自证，换层只是换了要自证的对象。**

一条在所有注入下都不红的差分测试，与一条不会失败的门是同一个东西，只是换了层。故 A28 的性质差分测试**自身必须先被"当前等价但独立的实现"注入证明会红**，该条列为差分机制验收的第一项。


## 18. 裁定 A32：三道机制互补已由测量证实；不为不存在的东西制造证据（G0 OR-02 R58，changeLog #58）

### 18.1 §15 A28 的"差分不取代禁令"由设计主张变为测量结果

G2 用四条**"当前等价但独立"**的注入各跑两遍（`-k differential` 只跑差分 / 全部 36 条），结果：

| 注入 | 只跑差分 | 三道合计 |
|---|---|---|
| `vision.expected_rows` 改回整秒整除（**S33 原形**） | 未抓到 | 抓到 |
| `expected_rows` 改闭区间计数（多 1） | **抓到** | 抓到 |
| `partition_check` 中段改相邻时间差（**S40 原形**） | 未抓到 | 抓到 |
| `kernel_a` 中段改 `o - prev > iv`（**S37 原形**） | 未抓到 | 抓到 |

**差分单独 1/4，三道合计 4/4。**

**G0 独立核验其关键论断**（"三条抓不到不是差分失效，是没有可抓的东西"）：直接对拍 `grid_points_between` 与旧式整秒整除，遍历 **126 个可达 period×interval 组合，分歧 0**。**在消费方实际能收到的全部输入上两式恒等，差分报绿是正确的。**

**结论**：抓到它们的是**禁令**，因为其毛病不是"算错了"而是**"同一条规则被独立写了第二遍"**。**重复今天不致错，明天才致错**——S32/S33 当时正是"当前等价"，靠的是运气。

**这张表同时构成一条反证**：若将来有人以"差分已覆盖语义"为由删掉禁令，第 1/3/4 行会立刻全部变绿，**而那三条正是 S33/S40/S37 的原形，是本项目已实际发生过三次的缺陷**。

**三个谓词，互不覆盖**（G2 表述，G0 采纳）：禁令对**重复**敏感（且是**不可达区域唯一有效**的机制——§5.16 B14 的 `multiplier` 位置行为测试跑不到）；差分对**偏离**敏感（与写法无关，但**只在真有分歧的输入上有效**）；登记对**绕过**敏感（含已登记调用方**内部单个使用点**的绕过）。**任何一道单独使用都会漏掉另外两道负责的那类。**

### 18.2 `force_close_net_R` 无消费方，差分不适用 —— 准

差分断言的是"**消费方实际行为** == 由单一来源直接算出的预期"，而 `force_close_net_R` 目前**没有消费方，等式左边不存在**（§5.21 B19 裁定 G3 只调用不自算，而 `research/` 尚未接入）。

硬写一条只能在测试里调用它、再拿一份**按同一公式重写的预期**去比——那等于同时犯两条：**把估值公式实现第二遍**（族 A），以及**让夹具冒充消费方证据**（§16 A29 第 1 节刚裁过）。

**裁定**：列"**无消费方，差分不适用**"，义务**顺延至 G3 接入时**，且须**明确留记录而非 `skip` 了事**——`skip` 只说"没跑"，不说"为什么不该跑、何时该跑、谁负责"。

### 18.3 一般原则：不为不存在的东西制造证据

本原则本轮**第三次适用**：

1. 跨窗口登记为**空集**，不预登记尚不存在的 G3 调用方（§16 A29 第 1 节）；
2. 夹具证据**不冒充**真实消费方的 θ 消费证据（同上）；
3. 差分对**无消费方**的单一来源**不适用**（本节 §18.2）。

**三次都是同一件事。** 制造出来的证据会让对应的门**因错误的原因通过**，于是**它在最该说话的时候沉默**——这与 §10 A22 的"无法失败的检查"、§9.10.17 A27 的"因噪声触发"同属一族：**门不携带信息**。

**配套义务**：凡因"对象不存在"而不适用某道机制，**必须显式记录三件事**——不适用的理由、义务顺延给谁、何种事件触发该义务生效。**只写"不适用"而不写这三条，与写一条假证据的区别只在于前者更容易被发现。**


## 19. 裁定 A33：隔离取证器必须自证确已隔离；"不适用"是带到期日的欠条（G0 OR-02 R60，changeLog #59）

### 19.1 隔离不等于已隔离 —— A29 第 2 节之上再加一层

§16 A29 第 2 节裁定突变取证须"真实写盘 + 子进程隔离"。**本轮证明该条仍不充分。**

G2 的承包方在做 `force_close_net_R` 的突变取证时，**隔离副本继承了祖先 `pyproject.toml` 的 `pythonpath=真实 src`**，于是子进程导入的是**真实模块而非副本**，注入后测试**仍绿**。G0 读取其自审记录 `tests/market/force_close_harness_audit.json` 逐字确认：

> "A26 叠加仍绿：隔离副本继承祖先 `pyproject.toml` `pythonpath=真实 src`，未执行突变模块。属验证器路径错误，修复为隔离 `pytest.ini`，并在每次 subprocess 启动断言模块 `__file__` 位于副本。**此记录不是通过证据。**"

G2 事后在真实树上注入同一条缺陷得 **5 failed**——**那次绿确实是取证器没把突变喂进去，不是测试无效**。

**危险在于不对称**：取证器失效产出的是**绿**，而绿正是会被读成"无缺陷"的那个结果。这是 §10 A22"无法失败的检查"在**取证器层**的又一次现身——**子进程隔离了，但导入没隔离**。

**裁定（A29 第 2 节的追加要求）**：
1. **取证器必须自证确已隔离**：每次子进程启动时断言被测模块的 `__file__` 位于副本内（承包方已采用的修法），或等效的路径归属断言；
2. **取证器投入使用前须先过一次活性检验**：注入一条**必须变红**的缺陷，确认它确实变红；**未过活性检验的取证器，其任何绿结果不得采信**；
3. **仅"子进程 + 真实写盘"不构成隔离证明**——继承的配置、环境变量、已安装包、`conftest.py` 都能把导入拉回真实树。

### 19.2 "不适用"是带到期日的欠条（采纳 G2 对 §18 A32 的重述）

§18 A32 要求"不适用"须记三件事（理由 / 义务顺延给谁 / 触发事件）。G2 给出更准的表述，采纳：

> **该要求把"不适用"从一个豁免重新定义成一个带到期日的欠条。豁免不需要任何人再回来，欠条有触发事件、有债主。**
>
> **没有触发事件的"不适用"会随时间沉淀成"已覆盖"**——不是因为谁撒谎，而是因为后来的人读到的只是一个静态的"不适用"，**读不出它当初是有条件的**。

**G0 核实其记录已齐备，无需补工**：`tests/market/test_single_source.py` 模块 docstring 与 `contract.py:653-657` 函数 docstring 各写明理由（"无消费方，差分不适用"、"不能在夹具中重写估值公式来制造等式左边"）、债主（G3）、触发事件（"G3 接入时"）。

### 19.3 附记：把"能交上去的绿"主动标成"不算数"

承包方手里已有一份**可以当作成功交付的输出**（注入后测试绿、SHA256 一致、三阶段齐全），却自行诊断出取证器路径错误，并在记录里明写"**此记录不是通过证据**"。

**这比停下提问更难**：提问是遇到墙；这个是**已经绕过了墙，却回头说这条路不算数**。§9.10.16 A20 第 4 节已立"撤回过度声明是必要条件"，本例是其更强的形式——**在没有人会发现的情况下主动作废自己的通过证据**。记为判例 5。


## 20. 裁定 A34：同批活性证据优于批前检验；实现本身必须入库（G0 OR-02 R61，changeLog #60）

### 20.1 §19 A33 第 2 条按 G2 所请加强：活性证据须在**同批内**

A33(2) 原文要求取证器"**投入使用前**过一次活性检验"。**G2 指出该口径留有窗口，论证成立，予以修订。**

> 取证器状态可能在**检验与使用之间**改变——配置被改、环境变量、缓存、并发写入。**批前检验只证明了"那一刻它是活的"。** 而同一批次里既有 RED 又有 GREEN 时，**那些 GREEN 是在已被证明有效的取证器上产出的**，时间上无缝，中间没有可以出事的窗口。

**这与 §17 A30"测量时刻是证据的一部分"同源**：一个与它所认证的使用**在时间上分离**的检验，留下的正是那段分离。

**修订后的 A33(2)**：
1. **每批取证必须在同批内含至少一条已知必红的对照注入**；
2. **仅当全批皆绿时**，才回退到批前检验，**且须重跑**；
3. 三批现状经 G2 自核：`mutate.py` 8 例含 7 RED、`mutate_forceclose.py` 7 例含 7 RED、`mutate_a28.py`（`-k differential`）4 例含 1 RED（闭区间计数 +1 那条）——**每批同批内均有 RED，活性已在各自批次内证明，不需补跑**。

### 20.2 G2 对自身取证方法的自陈：不是更安全，是换了一种风险

G2 主动说明其三个取证脚本**不建副本、直接在真实树上写盘注入再还原**（还原以 sha256 校验），故 A33(1)/(3) 的"子进程隔离了、导入没隔离"在其方法上不存在——**但明写这不是更谨慎，而是把风险换成了另一种**：任何一次未完成的还原会**直接损坏生产源码**，而 `finally` 同样挡不住 `SIGKILL`——**正是它上一轮要求承包方修掉"测试写生产文件"时给出的同一条理由**。

**G0 采纳该自陈并立为规则**：**不得以"我的方法没有那个失效面"论证方法更安全。** 每种取证方法都有其特有失效面，须**显式声明本方法的失效面与对应护栏**：
- 副本法：失效面是**隔离链断裂**（继承配置/环境/包/`conftest`），护栏是 §19 A33(1) 的路径归属断言；
- 真实树法：失效面是**残骸**（中途被杀留下已突变的生产源码），护栏是**批前批后各断言一次工作树与已提交基线一致**。

## 21. 裁定 A35：基线必须先于它所认证的过程；入库状态列为每轮必报量（G0 OR-02 R63，changeLog #61）

### 21.1 G2 自报的取证盲区，与"基线"的一般定义

G2 此前每条突变均报"还原 sha256 一致"，但其比对基线是**该 case 开工时读到的文件内容**。故该检查只能证明"**这条 case 没留下残骸**"，**证明不了"开工时树上没有上一批的残骸"**——前一批若留下突变，后续每条 case 都会忠实保留它并照常报"一致"。

**一般规则**：**基线必须先于它所认证的过程，不能由该过程自己采集。** 由被认证过程在自身起点采集的基线，对**早于该起点的污染完全失明**；它回答的是"我没弄坏什么"，不是"开始时是好的"。这是 §10 A22 一族在取证器上的又一变体——**一个只与自己比对的检查，其失败模式恰好落在它看不见的那一侧**。

**并记明其时序**：该盲区在 `bef5750` 之前**无法修复**，因为不存在可比对的基线。**故 §20.3 的入库不是顺手发现的问题，而是该护栏能成立的前提。**

### 21.2 护栏须先自证会红（G2 已执行，记为合规范例）

G2 落 `tree_guard.py`，四个取证脚本批前批后各断言工作树与已提交基线一致，不一致抛 `DirtyTree` 并列残骸文件、拒绝开工；**并先证明该护栏自己会红**（故意追加一行 → `DirtyTree` 列出该文件；`git checkout` 还原 → 无残骸）。

**这是 §19 A33(2) 与 §20.1 同批活性口径的正确应用**：**先证明护栏会红，再用它去认证别的批次**——否则它是又一条"认证别人却没人认证它"的检查。

**附一条要求**：`tree_guard.py` 自身按 §20.3 必须入库（G0 实测其当前不在树内）——**认证链上的工具与它认证的对象同列**。

### 21.3 裁定：入库状态列为每轮必报量，但**不做成 pytest 断言**

G2 问"跟踪率 100%"要不要立成三窗口共用的检查。**裁定：立，但不立为测试断言。**

**理由**：新文件从创建到 G0 提交之间**合法地处于未跟踪状态**。把"跟踪率 100%"写成常驻断言会**对正常在途工作持续报红**，而 §14 A26 已述其归宿——**假警报最终会被人关掉**。

**改为两条**：
1. **G0 每轮评审必须报告入库状态**：`src` 与 `tests` 的 `.py` 跟踪率，以及未跟踪文件清单。**本轮实测：`src` 48/48、`tests` 56/58，未跟踪两个均为 G2 在途的 `verify_s42_s43.py` / `verify_s43_archive.py`。**
2. **G0 在三窗口均出写入窗口时提交当轮新增**（§17 A30 的时序要求）。

**为何这样有效**：R38 与 §20.3 的失效不在于无人检查，而在于**从未有人看**。把它变成每 20 分钟被读一次的一行数字，其漂移就不再需要有人"想起来"——**这与做成断言的区别是：断言要求它恒为真，必报量只要求它恒可见。**

### 21.4 归因：采纳 G2 的结构性观察，与 §17 A30 一致

G2 指出 R38 与 §20.3 的共同形状是**"产出物入库了，产出物所指向的对象没入库"**，且**两次都不是因为有人检查"入库了吗"而被发现，是因为有人要用它**——R38 是要援引证据，本次是 G0 去落实 G2 的护栏时发现没有基线。

其结论予以采纳：**"是否入库"这类属性，在被使用之前不可观测**——不报错、不变红、不在任何测试里显形；`pytest` 全绿、审查方报"SHA256 未变"，全都照常，因为**那些检查从不问"这棵树有没有提交可以印证"**。

**故按 §12 A24 第 2 节记为"依赖人记得的机制失效"之实例，而非记为"G0 两次疏忽"**——归因落在能自动生效的那条（§21.3 的必报量），与 §17 A30 采纳同一论证时的处理一致。**事实不变：提交义务在 G0；改进方向落在机制。**


## 22. 裁定 A36：边界覆盖必须逐类以突变证明，不得以"已声明覆盖"代替（G0 OR-02 R65，changeLog #62）

十二审（终裁 fail，阻断项 S42/S43）独立复做了两批突变并**逐条验证十条差分各自能失败**，且**明确不把静态门的失败计给差分**——正是 §15 A28 要求的机制隔离。其对 §18 A32"三道互补"原则**予以认可**，同时指出该轮把 kernel 相邻比较也概括为"全部可达输入恒等"**依据不充分**，反例即 S42。

### 22.1 S42 的实质：不是第三层被穿过，是第三层没有按规格实现

**这个区分必须写清楚，否则会导出错误的改进方向。**

§15 A28 已**显式列出**离网边界为生成器必须对抗覆盖的四类之一。而十二审查明：

- **kernel 生成器只用 `_grid(start,end)` 的子集造 bar**，时间边界变化改的是请求 `start/end`，`bar.open_time` **始终落在精确网格上**；
- **lake 生成器同样**只把区间内完整网格或其子集交给消费方；`start−1µs / end` 位于**窗口外**，**不构成窗口内离网 bar 的对抗覆盖**；
- `partition` 生成器确实覆盖了离网点，但**另一个消费方的覆盖不能替代 kernel/lake 各自的输入路径**。

**故 A28 没有被穿过；A28 的义务没有被履行。** 生成器从未产生过"窗口内的离网 bar"，因此那一类边界**从未被测试过**。

**注入的真实性**：把 `KernelA._first_bar_gap` 收集 opens 改为 `b.open_time.replace(microsecond=0)`，是**族 B 的真实秒级截断**，非任意常数或异常；在当前生成器产出的全部 bar 上**等价**，故三道门 36 条全绿。而公开 `simulate` **可以接收 +1µs 的 bar**：未突变 `FIRST_GAP=01:01:00 / censor_reason=BAR_GAP / bars_ok=False`；注入后 `FIRST_GAP=None / censor_reason=LABEL_RIGHT_CENSORED / bars_ok=True`。

**后果的性质与 §9.10.11 A15 同族**：删失原因由"**我们有数据缺口**"（我们的事实）被静默改写为"**观察终点仍持仓**"（世界的事实）——**两种不同的现实被合并**，而这正是当初设立 `unevaluable` 要分开的那条界线。

### 22.2 裁定：修复必须在输入域，不得以 lint 字符串禁令冒充

十二审已预先堵死那条便宜路，G0 予以采纳并立为规范：

> **不把添加一条 `replace` 字符串禁令当作第三层已经修复。**

加一条枚举写法的禁令是**退回第二层**——§15 A28 已判该方向不可封闭。**修复验收须在真实消费路径上覆盖窗口内 `−1/0/+1µs` 离网类，并证明"拒绝/隔离"或"行为偏离"会红。**

### 22.3 一般规则：边界覆盖须逐类以突变证明

§15 A28 要求生成器"在边界类上是对抗性的"。**S42 表明，该要求在未被验证时只是一句声明**——生成器可以完全满足字面（有时间边界变化）而**从未产生该类的真实实例**。

**裁定**：A28 所列每一个边界类（时间边界 / 数值边界 / 空与缺失 / 跨分支等价对），**必须各自配一条只有该类能捕获的突变，并证明它变红**；未能给出该突变的边界类，**视为未覆盖**，不得以"生成器已包含该维度的参数"充数。

**这是"门须自证会红"（§12 A24、§19 A33）向下再走一层**：此前证明的是**门**会红，现在要证明的是**生成器的每一类输入**能让门红。**一个能红的门配一个到不了的输入，合起来仍然是绿的。**

### 22.4 附记十二审的两处克制，均予采信

1. **"闭合不外推为整个家族永远无遗漏"**——S29/S31/S32/S33/S35/S37/S38/S39 与十一审 S40/S41 原形均 closed，但审查方拒绝把"指定落点已闭合"外推为"该族已绝迹"。
2. **"本轮 24 个已选突变全部检出也不证明边界输入生成完整"**——拒绝以检出率反推覆盖率。

**两处都是拒绝把"已验证的部分"说成"全部"**，与 §10 A22 第 3 节"只报证据支持的结论"同源。


## 23. 裁定 A37：快照基线须"归因"而非仅"记录"；两向错误代价不对称时门须偏向廉价的一侧（G0 OR-02 R66，changeLog #63）

### 23.1 裁 G2 所问：护栏基线以 HEAD 为准，还是允许批前快照？

**背景**：G0 按 §17 A30 在 research 处于写入窗口时**推迟提交**，故工作树与 HEAD 长期有差异。G2 的真实树护栏改用**整批开工前采集的快照**为基线，并**显式记录该快照与 HEAD 的差异**（上批记 `HEAD=254e3ad`、差异 9 个文件、批后 106 个文件逐一回到快照）。

**裁定：允许快照基线，但"记录差异"不足，必须"归因差异"。**

- **不采用 HEAD 严格口径**：正常在途工作会使 HEAD 恒不干净，护栏将无法开工——这会把它变成 §14 A26 所说"终将被关掉"的那种门；
- **仅"记录"亦不足**：§21 A35 判过"由被认证过程在自身起点采集的基线，对早于该起点的污染失明"。快照把污染**变可见**，但**看见不等于分辨**——一条上批残留的突变，与一条合法在途修改，在快照差异里长得一模一样。

**故立第三条口径**：批前须**声明预期差异清单**（本窗口自己改过的文件），护栏断言**实际差异 == 声明差异**；**出现任何未被归因的差异即拒绝开工**。这与 §12 A24 调用点登记同形——**声明集合 == 实际集合**，差集非空即红。

**记录 → 归因**的差别是：记录让人**事后能查**，归因让机器**当场能拒**。

### 23.2 采纳 G2 对 §22 A36 后果性质的推进：两向错误代价不对称

G0 在 §22 A36 记该后果"与 §9.10.11 A15 同族：我们的事实被写成世界的事实"。**G2 指出方向是单向的，且两向代价不对称**，予以采纳：

| 错误方向 | 后果 | 代价 |
|---|---|---|
| 世界的事实 → 误记为我们的缺口 | 样本进 `unevaluable` 被排除 | **统计效率** |
| **我们的无知 → 改写为世界的中性事实** | 样本**带着编造的世界事实进入 θ 的分母** | **结论本身** |

**A15 当初把两类删失分开，分的正是这条线。** 而 S42 是从**边界覆盖的空白**里漏进来的——**没有任何一道门说话**。

**由此立一般规则**：**当一个判定的两个错误方向代价不对称时，门必须偏向代价较低的一侧**，并在契约中写明偏向哪一侧与依据。对删失归因而言即：**证据不足时归入 `unevaluable`（我们的缺口），不得归入 `LABEL_RIGHT_CENSORED`（世界的事实）**——宁可损失统计效率，不可污染结论。

### 23.3 记 G2 的验收失误自陈

G2 自陈：其任务书原样抄了 A28 四类边界，验收生成器时**核了"有没有这个维度"，核到了就算过，但没核"这个维度有没有产生过该类的真实实例"**——**把"声明了"当成了"做了"**，并指出这与其上轮那条过度泛化同源：**都是只问了生成器生成了什么，没问消费方能收到什么**。

**该自陈正是 §22 A36 那条规则的存在理由**，故 A36 的判别性限定（"**只有该类能捕获**"）不可省略：G2 已有 **131 组突变全红**，而它们**一条也没能证明离网类被覆盖过**。**判别性是这条规则唯一起作用的部分。**

### 23.4 时序处置确认

A36 到达于十三审派出之后，该轮任务书未含此判据；G2 决定**不在本轮补派**（审查方正读树并做审前/审后 SHA256 比对，此刻改 `src/` 会毁其证据同一性），将四类边界的判别性突变列为**十三审回执后第一项**。**处置正确**，与 §16 A29 第 2 节、§20.2 同向。


### 23.5 修订 §20.3 / §21.3 的提交时序：改为**按模块**判定（G0 OR-02 R67，changeLog #64）

**起因**：原规则为"G0 在**三窗口均出写入窗口**时提交当轮新增"。该口径在实践中**连续两轮阻止提交**——research 持续在工作，而 data 与 market 早已空闲。后果有二：未提交工作累积；G2 的护栏被迫用快照基线而非 HEAD（§23.1）。

**修订**：**提交时序按模块判定**——某模块出其写入窗口即可提交该模块，不必等其余模块。

**依据**：该规则要避免的风险是**捕获半写文件**，而**该风险是按文件/按模块的，不是全局的**。原口径比必要更严，其代价（累积未提交 + 迫使护栏降级到快照）是真实的，而收益在模块相互独立时并不存在。

**本轮据此执行**：data 空闲 3 小时、market 空闲 5 分钟 → 提交（`4f911a5`，19 文件）；**research 距今 114 秒、在窗口内 → 保留至其下一个空闲窗口**。同时按 §21.2 收入 `scripts/tree_guard.py`——**认证链上的工具与它认证的对象同列**。

**附记**：本条修订由 G0 观察自身规则的执行代价而作出。**一条规则连续两轮阻止它本该促成的事，就该被检查是不是比必要更严**——这与 §14 A26"假警报终将被关掉"同源：**过严的规则不会被遵守，只会被绕过或搁置**。


## 24. 裁定 A38："同批"须以**选择器**定义；对照的绿必须携带信息（G0 OR-02 R68，changeLog #65）

### 24.1 G2 所请的 A33/A34 细化**成立**，并可给出更强的形式

G2 首次做同批活性对照时用 `vision.expected_rows + 1`，**四类全绿**，第一反应是怀疑取证器失效。真因是：**那四条 `test_boundary_*` 根本不测 `expected_rows`**——**该对照是本批选择器碰不到的**。换成消费方入口的无条件破坏（`grid_points_between` 恒返回 0）后四类全部 RED。

**G0 独立判断：细化成立，理由可比其表述更精确。**

对照的职责是证明**本批的"取证器 + 选择器"组合能把绿变红**。若对照不在本批选择器的可达范围内，**它只可能产出绿**，而这种绿**不携带任何信息**——它由两种情形**同样产生**：

| 情形 | 对照结果 |
|---|---|
| 取证器健康 + 对照不可达 | 绿 |
| **取证器失效** | 绿 |

**§19 A33 的存在理由正是"失效产出的是绿"**；一条**唯一可能输出是绿**的对照，恰好废掉了这条规则。

**更强的形式（G0 补）**：该要求**自带验证**——**若对照在本批实际选择器下变红，可达性即由那个红本身证明**，无须另做可达性论证。故规则可收敛为一句：

> **对照必须在本批实际使用的选择器下变红。**

**并据此消歧 §20.1 的"同批"**：G2 那次对照**与被测同处一次会话**，故按字面满足"同批"，却与被测**不同选择器**。**裁定："同批"以选择器同一性定义，不以会话或墙钟分组定义。**

### 24.2 与 §22 A36 是同一条谓词

- §22 A36：给不出**只有该边界类能捕获**的突变 → 该类视为**未覆盖**；
- 本节：给不出**本批选择器能捕获**的对照 → 该批视为**无活性证据**。

**两处要的都是判别性，不是"红过"。** G2 上轮写"判别性是这条规则唯一起作用的部分"时，未想到它**同样适用于对照本身**——**规则用于检验别人时是判别性，用于检验自己时也必须是判别性。**

### 24.3 判例 6：对别人要求集合相等，对自己写了单向检查

**S44 根因（G2 自陈，G0 核实）**：其快照护栏只遍历**快照内已有文件**问"变了没"，**没问"有没有多出文件"**——是一条**单向检查**。

**而同一工具内就有现成对照**：`scripts/tree_guard.py` 的 `assert_declared`（:102）用集合语义，**抓到了那个新增文件**；`assert_matches`（:78）没有，**没抓到**。**两条路径，一条有集合相等一条没有，同一文件、同一时间。**

**更值得记的是**：G2 在 §12 A24 中**要求他人的调用点登记必须是集合相等（新增与缺失都要红）**，而其自身护栏用了单向检查。

**故立一般义务**：**凡为他人立下的检查性质要求（集合相等、判别性、自证会红、基线先于过程），立规者须同期审计自己的同类工具是否满足**，并在看板记录该审计。**一条只用于约束他人的规则，其作者是它最不可能被应用到的对象**——不是因为双标，而是因为**立规时注意力在被规范的对象上，不在自己手里的工具上**。

### 24.4 A36 判别性矩阵首条对角线已验（G2 独立复核）

注入 S45 原样"前向 1µs 容差" → **时间类 RED / 数值 GREEN / 空缺失 GREEN / 等价对 GREEN**。**只红本类、他类全绿**，对角线成立。**这才是 A36 要的东西，不是"又跑了一批全红的突变"。** 其余三条对角线待十四审独立复核。


### 24.5 G0 按 §24.3 自审其工具，查出并修正自身门的缺陷（G0 OR-02 R69，changeLog #66）

§24.3 要求"立规者须同期审计自己的同类工具"。**G0 于本轮对 `tests/integration/test_e2e_synthetic.py` 执行该审计，结论如下。**

**第一步 · 自证会红（§12 A24 / §19 A33）**：注入 R28 的原始缺陷（resolver 不提供 `Rules` → 默认 `step_size=1` → 全部 `LOT_SIZE` 拒单 → 退化样本）。**基线 2 passed → 注入 2 failed → 清理后复跑 8 passed。门确实会红。**

**第二步 · 判别性（§22 A36 / §24.2）—— 查出缺陷**：构造一条"有成交但无人走完结局"的突变（价格恒为入场中值，永不触及 TP）。**两条门全绿。** 追查实际分布：`right_censored 78 / rejected 2`。

**根因**：G0 的断言写的是 `len(kinds) >= 2`——**两个零星的 `rejected` 样本即可满足它**。**该断言声称检查"样本非退化"，实际检查的是"至少出现两种标签"**；一个 78/80 停在删失、**无人走完任何结局**的样本，就这样通过了非退化门，而 θ 照常算出。

**这与 G0 反复裁给他人的形态同一**：**断言的字面与它声称的意图不符**，且**一个零星取值就能满足字面**。

**修正**：改为断言**真正走完结局的样本占比**——`outcome_kind ∈ {tp_hit, stopped, filled_closed}` 的行数须 ≥ 总数的 1/4；并保留"全部未挂出/不可评估"的原断言。

**修正后判别性成立**：同一条判别性突变下 **非退化门 RED / 主断言 GREEN**——该门现在捕获主断言捕获不到的东西，符合 §22 A36 的对角线要求。基线 8 passed。

**记明本条的意义**：§24.3 立于上一轮，**其作者在下一轮即被它查出一处自身缺陷**。这佐证了该条的依据——**立规时注意力在被规范的对象上，不在自己手里的工具上**；而缺陷的形态与 G0 裁给他人的**完全相同**，说明该形态与身份无关，只与"谁在审查谁"有关。


### 25. 裁定 A40：写入窗口按**写入频率**判，不按单点 mtime；证据块不得含列首终裁行（G0 OR-02 R74，changeLog #70）

#### 25.1 单点 mtime 阈值会把活跃会话的间隙误判为空闲

**本轮实例**：G0 于 08:49Z 测得 research 最近写入距今 1074 秒（判为可判），随后跑完四套用时约 4 分钟；复核时发现 `tests/research` 在 **17:54** 与 **17:56:58** 各有一次写入——**即 G0 测量与判定之间该模块一直在被改**。最终距今 125 秒，**刚越过 120 秒阈值**，按字面可判，而实际是一次活跃会话的间隙。

**裁定**：写入窗口以**近期写入频率**判定，不以最近一次写入的单点年龄判定。**判据：最近 10 分钟内若有 ≥2 次写入，视为活跃会话，一律记"不判"**，无论最后一次距今多久。

**依据与 §17 A30 同源**：A30 立"测量时刻是证据的一部分"，本条补的是——**测量与判定之间的那段时间也是**。一次跑满四套约需 4–5 分钟，**单点阈值只约束了测量那一刻，没有约束判定成立的整个区间**。

#### 25.2 证据块不得含列首终裁行

`review-G3-P1.md` 现有 **4 处** `五审终裁：fail`：**3 处在证据代码块内**（tail 检查命令的输出回显），1 处是文件真实末行。

**本次无害**（四处同值，且 R-10 的 verify 取**文件末行**），**但两种 verify 的脆弱面不同**：
- G3 的 `tail -1 <file>`：对块内行免疫，**但若日后在终裁后追加任何内容即失效**；
- G2 的 `grep 终裁 | tail -1`：对追加免疫，**但会读到块内行**。

**裁定（从源头消除，而非要求每条 verify 各自绕开）**：**审查报告的证据块内不得出现列首的终裁形状行**——回显该行时须缩进或加引导符。§9.9 A7 要求"终裁行唯一可判读"，本条是其落地形式。

#### 25.3 记五审的实质发现

五审终裁 fail：**S08 闭合**（代码/后端血缘与复用口径），**S17 部分闭合**，**S10 由已闭合改判部分闭合**——理由是"**新增弱相关机制破坏暴露既有总体判据盲区**"，且明写"**不能把'旧回归全绿'写成完整闭合**"。

**核心发现**：**结构失败没有被强制纳入 `n_failed`，能使本应超过 7% 的条件 FPR 最坏界假绿。** 这是 §10 A22 一族——**一道在特定方向上不会失败的门**，且方向正是"把不合格判成合格"。

**其"旧用例无回退，新覆盖揭露旧盲区"的表述值得采信**：它把"回归全绿"与"覆盖完整"分开，与 §22 A36"检出率不反推覆盖率"、§18 A32"闭合不外推为家族无遗漏"同源。


### 25.4 把审查发现写成先行失败的测试，是进度而非回归（G0 OR-02 R75，changeLog #71）

**本轮实例**：`tests/research` 10 failed / 341 passed，**按 §25 A40 判定有效**（判定后复核：跑测期间该模块 0 次写入）。逐条归类：

### 25.5 绕开的报错常常就是要找的不变式（G0 OR-02 R78，changeLog #72）

G3 自陈一处与其被审对象**同形**的错误，并给出一条 G0 认为值得固化的归纳。

**事实**：五审指出 G3 上一轮的测试 helper **也只搬档位、不付失败费**。G3 承认属实，并说明当时的经过——把 50 条搬进 `invalid` 时撞上「**报告算术不一致**」，**选择了绕开，而没有追问算术为什么会破**。而破掉的，**正是那条记账不变式**（结构失败必须计入 `n_failed`）。

**G3 的归纳，予以采纳并立为一般教训**：

> **测试里为了让断言跑通而绕开的那个报错，往往就是你要找的不变式。**

**机制**：写测试时遇到非预期报错，最省事的处置是**改造输入直到报错消失**，好让原本要断言的那件事能跑起来。但报错本身是系统在说"这个状态不合法"——**绕开它等于把"系统拒绝了我构造的状态"当成了障碍，而不是当成信息**。若被断言的性质恰好依赖那条不变式，绕开之后断言仍会通过，**而它已经不再测原来那件事**。

**处置要求**：测试构造过程中遇到被测系统主动抛出的错误时，**须先确认该错误与被测性质无关，方可改造输入绕开**；确认过程写进测试注释或看板。**不得以"改了输入就不报错了"作为绕开的理由**——那恰恰是该追问的时刻。

**并记 G3 补的一条证据，它把该门的性质说清楚了**：付清失败费之后，同一份记录按 `FPR 未通过` 被拒，上界 **8.020159%**，与五审独立算出的 `minimum_correct_upper` **逐位相同**。**即该门不只是"拒收畸形载荷"，而是在正确记账下真的把 `pass` 翻成了 `fail`**——这才坐实了五审那句"失败方向是把不合格判成合格"。

### 25.7 修订 §25 A40：活跃判据应为**析取**，不是替换（G0 OR-02 R79，changeLog #73）

**本轮实例**：research 在测量时刻 **22 秒前**刚被写入，但近 10 分钟只有 **1 次**写入。按 §25 A40 的字面（"≥2 次即活跃"），**它不算活跃、应当可判**——而一个 22 秒前刚被改过的模块显然是移动靶。

**根因：G0 在 §25 A40 中用频率判据 *替换* 了单点 mtime 判据，而非与之 *合取*。** 两个信号捕捉的是**不同情形**，互不包含：

| 信号 | 捕捉 | 漏掉 |
|---|---|---|
| 单点 mtime < 120s | **刚刚写过** | 会话中的长间隙（§25 A40 的原始动机） |
| 近 10 分钟 ≥2 次 | **会话进行中** | 单次写入但极近（本轮情形） |

**修订后的判据（析取）**：满足**任一**即视为活跃、记"不判"——
1. 最近一次写入距今 **< 120 秒**；**或**
2. 近 10 分钟内写入 **≥2 次**。
判定后须按 §25 A40 复核**同一析取**。

**一般教训（G0 自省，与 §25.5 同类）**：**修一条失效的规则时，先确认是在补充信号还是在丢弃信号。** A40 立于观察到单点阈值被"会话间隙"骗过，正确的反应是**再加一个信号**，而 G0 把原信号整个换掉了——于是刚修好的规则立刻在**另一侧**被骗。**一条规则失效，不等于它捕捉的那件事不再需要捕捉。**
