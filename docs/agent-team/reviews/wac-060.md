原因：Caddy `MatchPath`（v2.10.2 `modules/caddyhttp/matchers.go:429-533`）先把占位符替换为空，含 `%` 的模式在转义空间里比较；只有"两端都是 `*`"、"只有一个 `*` 且在开头或结尾"三种情况走快速路径，其余都交给 `path.Match`，支持 `?`、`[...]`、`\`。而 `_caddy_path_match`（`o0_caddy_watcher_routes.py:368-383`）把 `*` 以外的字符一律 `re.escape` 当字面量处理。遮蔽检查第 1 步（`_mset_may_hit` `:591-593`）和逐行模拟（`_match_one_set` `:402-404`）都用这个函数。

`%77` 形式我也测了：Caddy 与工具的判断一致，都判不命中，没有漏判。

## 7. 🟡 建议（按阻断的授权排序）

1. **（O0-A05 与 O0-A05P 之前）`path` 匹配器的模拟缺少 glob 与占位符语义，遮蔽检查会漏判**（`o0_caddy_watcher_routes.py:368-383`，被 `:591-593` 和 `:402-404` 调用）。实证见 §2.3：带 `?`、`[...]`、`{占位符}` 的顶层 rewrite 和 request_header 都能通过 verify，其中 request_header 那一例连探针也能通过，并且会注入 observer token。
   - 修法：模式在转小写后含 `?`、`[`、`]`、`\`、`{`、`}`、`%` 中任一字符时，`_mset_may_hit` 按命中处理，`_match_one_set` 抛 `Uncomparable`（宁可误拦，与 F-13 "无法评估即命中"一致）；或者逐条照搬 `MatchPath.MatchWithError` 的算法。
   - 同时修正 `o0-requirements.md` §10.6 第 4 条的"其他一律 UNCOMPARABLE"，这一说法对 `path` 模式并不成立。
   - 补测试：selftest 加入 `?`、`[w]`、占位符三种模式；`caddy_real_test.sh` 加入 §2.1 的三个漏判变体和 §2.3 的注入变体。
   - 探针里每条表内路径的 `forwarded()` 都带上假的 Authorization，并断言原样到达，这样凡是改写请求头的遮蔽都能被探针抓到。
2. **（O0-A05 之前）转发检查按字面上游字符串识别 operator-query**（`:777`）。`reverse_proxy localhost:8183` 可以绕过，而 runbook §3.1 第 3 条写的是"不论写在 import 前后都判失败"。修法：operator-query 按端口 8183 识别，不看主机部分；无法解析的 dial（主机名、占位符、unix socket、`dynamic_upstreams`）一律按 UNCOMPARABLE 判失败。`path` 模式在转小写后以 `/m/v1/watcher` 开头的，直接视为命中前缀，不只依赖固定探针（死配置 `handle /m/v1/watcher/extra` 也会顺带被抓）。
3. **（O0-A05P 之前）探针看不到没有被替换的上游**（`probe_caddyfile` `:1244-1247`，`not_forwarded` `:1363-1366`）。修法：adapt 之后、`caddy run` 之前，列出 adapt 结果里所有的 `reverse_proxy` dial，只要有一个不是两个桩之一就拒绝运行（或者统一改写到一个关闭的本机端口），并把替换过的 dial 列表打印进证据；全局选项加上 `default_bind 127.0.0.1`（实测探针期间 Caddy 监听在 `*:<端口>`）。
4. **（O0-A05P 之前）探针的遗留文件与证据绑定**：
   - `.o0probe` 写在 `try` 之外（`:1310-1311`，`try` 从 `:1337` 开始），adapt 失败或更早抛异常时，含 bcrypt 哈希的 `.o0probe` 和临时 XDG 目录都会留下（已实测）。修法：写文件之后的全部逻辑放进同一个 `try/finally`。
   - 探针不打印副本与片段的 sha256，所以 A05 的"A05P 结果为 `CADDY_PROBE_OK`"这一前置条件无法机械地绑定到 C-1 门禁里的候选 sha。修法：打印这两个 sha，由 C-1 或 runbook 要求它们与候选相等。
5. **测试缺口（质量项，建议随 🟡-1 一起补）**：§4.2 列出的 8 个存活变异。优先补 G24、G25：在 `caddy_real_test.sh` 里把 `HOME` 设为哨兵目录再跑 probe，断言其中没有写入任何东西；断言 `.o0probe` 含 `admin off`。其余依次是 G13、G17、G18、G26、G37、G10。
6. **（O0-A05 之前，小项）preflight 的写入范围**：`SNIPPET_STAGED` 取自 `dirname(CANDIDATE)`（`o0_deploy_caddy.sh:58`）。如果 `--candidate` 指向 `/etc/caddy/…`，只读的 preflight 会把片段装到 `/etc/caddy/caddy-watcher-gateway.caddy`，apply 随后把它记成"原本就存在"，回滚时也就不会删除它。修法：`SNIPPET_STAGED` 不在 `$O0_STAGE_DIR` 之下、或者等于 `SNIPPET_LIVE` 时直接拒绝。
