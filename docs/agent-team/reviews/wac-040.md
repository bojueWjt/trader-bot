## 6. 🟡 建议（不阻塞合并，建议并入 wac-015 或 O-0 前的打包收尾）

- **🟡-1 闭包对非字面量 require 是"无法看见 = 通过"**（`tests/deployment/test_watcher_package_contract.py:17`）。正则只匹配 `require('./...')` 与 `require("./...")`。模板字符串、`path.join` 拼出来的 require 会被静默跳过（M8、M9 存活）。现在代码里没有这种写法，但闭包测试要长期守门，不能把"解析不了"当成"没有依赖"。建议再加一条扫描：凡是参数不是纯字符串字面量的 `require(`，一律断言失败（显式允许 `node_modules` 包名字面量）。这样新写法会让测试变红，逼人把白名单和测试一起改。
- **🟡-2 compose 测试不守 healthcheck（E-16）**（同文件 71-98 行只检查 `environment`；`bridge/docker-compose.yml:163-170`）。任务要求 healthcheck 在 node 脚本里读 `process.env`、不插值。本次确实没改（已核对 diff），但 M15（硬编码）和 M16（`${...}` 插值）都不会让任何测试变红。建议断言 `healthcheck.test` 整体不含 `$`，也不含 `WATCHER_*_TOKEN` 以外形式的凭据，并且包含 `process.env.WATCHER_BROWSER_PROXY_TOKEN`。
- **🟡-3 `env_file` 为必需文件，影响整个 compose 项目**（`bridge/docker-compose.yml:129-130`）。Compose v2 加载项目时会解析所有服务的 `env_file`，文件缺失时，对这个项目的任何 `docker compose` 命令都会报错，不只影响 watcher。这对凭据来说是正确的 fail-closed（不应加 `required: false`）。但 O-0 需要确认顺序：runbook W-3 先写 `/srv/trader-secrets/watcher-gateway.env` 再装新 compose，这点已满足；W-5 回滚用旧 compose，也不受影响。同时需要提醒：任何本地或 HK 上用这份 compose 起其他服务的人，都要先放一个空的占位文件。建议 Release Steward 在 `o0-runbook-deploy.md` W-3 与本地说明里各写一句。
- **🟡-4 compose 测试依赖系统 `python3` 带 PyYAML**（同文件 80 行）。本机 `python3` 有 PyYAML 6.0.3，`.venv-arch` 没有。缺库时 `check=True` 会让测试失败，这是 fail-closed，不会假绿。但它依赖的是 PATH 上的 `python3`，与路由生成器同一前提。建议在 `o0_package.sh` 的 G9 里显式检查 `python3 -c 'import yaml'`，免得打包机换环境后报错让人摸不着头脑。

## 7. 💭

- 💭-1 闭包只检查"被引用的必须在白名单"和"白名单里的必须存在"。"在白名单里但不再被任何入口引用"的 JS（比如以后删掉某个模块）不会报错。目前 `lib/generated/gateway-routes.js`（有意保留）以及 `lib/hermes-cron.js`、`lib/signal-importer.js`（预存、入口不可达）都属于这种情况。可以考虑一个显式的"非 require 进镜像"清单，把这种情况写成白名单里的例外。
