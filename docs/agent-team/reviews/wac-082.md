## 6. 分级意见

### 🔴-1 `scripts/dump-route-table.js:85`：路由路径不是字符串时，被当成"不在 /api 下"直接放行，属于把"无法比较"当成"相等"（红线 7）。与 integ 相比，这是检测能力的倒退。

```js
const routePath = typeof handler.path === "string" ? handler.path.toLowerCase() : "";
```

**问题在哪**
- 数组路径或正则路径注册的路由，`routePath` 会变成 `""`，于是既不算 `/api`，也不算 `/media`，永远不会进 `unexpected`。
- 同一个 diff 在 `:89` 对挂载做了正确处理：路径不是字符串就算 unexpected。路由这边的处理恰好相反。
- 这正是上轮 🟡-1 建议中"路径不是字符串时直接算 unexpected"要关闭的形式，只修了挂载，路由这边却从"会报错"变成了"静默通过"。

**实测**
- 注入：
  - `app.patch(["/api/rogue"])`、`app.patch(/^\/api\/rogue$/)`：exit 0，`unexpected=[]`。
  - 同样的 POST 形式：`sameShape` 在 `:70` 抛出 `TypeError`，没有 JSON 输出，但 exit 仍是 0（原因见 🟡-1）。
- 真实改动对照（`r083c/`）：在 `server.js` 里加一行 `app.patch(["/api/rogue"], …)`，然后运行仓库测试（`--test-name-pattern dump-route-table`）：
  - integ 版脚本：抛出 `handler.path.startsWith is not a function`，stdout 为空，仓库中 2 条 dump 测试**变红**；
  - 分支版脚本：exit 0，`unexpected=[]`，3 条 dump 测试**全绿**。
- 结论：这次改动之前，这种 rogue 路由会让测试变红；改动之后，测试是绿的。

**现实影响**
- 鉴权中间件先执行，表外的 PATCH 请求到不了这个 handler，所以不是运行时漏洞。
- 但 §9.14.4 第 3 项的"不存在 payload 之外的 `/api/*` handler"这项 diff 判定，对这种形式失明了。

**修复建议**
1. `handler.path` 不是字符串时，直接推进 `unexpected`（写法与 `:89` 对称），不再参与前缀判断。
2. `sameShape` 遇到不是字符串的 `actual`，返回 `false`，不要抛错。
3. 在 `auth-media.test.js:208-219` 的注入表中增加 `app.patch(["/api/rogue"])`、`app.patch(/^\/api\/rogue$/)`、`app.post(["/api/rogue"])` 三种形式，都断言 `status === 1`。

### 🟡

**🟡-1 `dump-route-table.js:17-103` 与 `server.js:44-47`：脚本运行中的任何异常都会以 exit 0 结束（预存问题）。**

- 原因：`require("../server")` 会安装一个 `uncaughtException` 守护，它只打日志，不退出。
- 后果：脚本自己的 fail-closed 检查 `throw new Error("watcher authentication route table is not mounted")`（`:47-48`）也被这个守护吞掉。我用 preload 摘掉 `routeTable` 实测，分支和 integ 都是 exit 0。
- 目前为什么没有假绿：仓库测试都会 `JSON.parse(stdout)`，崩溃时 stdout 为空，测试会变红。但如果有人把这个脚本当作只看退出码的 CLI 门禁，崩溃就会被当成通过。
- 建议：
  - 在 `try` 后加 `catch (err) { process.stderr.write(...); process.exitCode = 1; }`（不要 rethrow，因为守护会吞掉）；
  - 或者在 `require("../server")` 之后移除这两个监听器；
  - 同时加一条测试：摘掉 `routeTable` 后，断言 `status === 1`。
- 可以和 🔴-1 一起改，改动很小。

**🟡-2 其余几种绕过形式（新发现，不属于上轮列出的范围，不作为 FAIL 理由；真正的防线仍是鉴权中间件）。** 下面这些注入在分支上都是 exit 0，`unexpected=[]`：

| 注入 | 为什么漏掉 |
|---|---|
| `app.all("/{*splat}")`、`app.post("/:a/login")` | `:86` 只检查字面前缀 `/api`、`/media`。第一段是参数或通配符的路由，运行时能匹配 `/api/*`，但不会被检查到 |
| `app.router.use("/api", fn)` | 直接调用 router，绕过了 `express.application.use` 钩子，`mounts` 里没有这条记录；`collectRoutes` 又只看路由层 |
| 在根路径再挂一个 `express.static("/")` | 工厂函数是已知的，但数量和目录都没有校验 |
| 重复注册合法路由（`GET /api/status`）、大小写变体（`GET /API/STATUS`）、`GET /MEDIA/:f` | 目前是集合成员判断，不是一对一匹配 |

建议：
- `unexpected` 改为"不能匹配任何身份行的路由，一律算 unexpected"，只白名单 `GET /healthz`；
- 非路由层直接遍历 `app.router.stack`，逐层用 `known.*.has(layer.handle)` 核对，不再依赖 `use` 钩子；
- 每个身份行必须恰好对应一个 handler；
- static 挂载必须恰好一个。
