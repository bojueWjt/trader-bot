## 5. 🟡 建议

1. **自动回滚在 restart 之前失败时也会 restart，而且自动回滚之后不跑舰队守卫**（`o0_deploy_caddy.sh:94-101`、`:114`、`:128`；`o0_deploy_watcher.sh:151-167`、`:198`、`:217`；`o0_deploy_operator_query.sh:102-113`、`:132`、`:144`）。Caddy 的 trap 从备份之后就生效。之后的 env 合入、安装、sha 核对、validate、adapt/verify 任一步失败，`rollback_files` 都会执行 `systemctl restart caddy`，可此时运行中的 Caddy 从未变过，只还原文件就够了。这等于在一个本可无风险退出的路径上引入 D-02 的全舰队 HALT 风险。watcher（多一次重建、多一段信号空窗）和 operator-query 同理。另外 trap 只做 `rollback … ; exit 1`，回滚里如果发生了 restart，脚本不做守卫比较，HALT 只能靠人发现。修法：restart/recreate 步骤成功后置 `O0_RESTARTED=1`；回滚在未 restart 时只还原文件并 validate；已 restart 时回滚后跑一次 `o0_fleet_settle_compare`（只报告，不设门槛），并把结论打印在退出前。**申请 O0-A05 之前必须修。**
2. **脚本步骤顺序没有测试守护**（变异 1g、3g、4d、4e 存活）。建议加一个 plan 模式结构测试：解析各阶段 PLAN 输出，断言 apply 第一步是 `REQUIRE passed … gate`、舰队基线在第一个写入之前、trap 之后才有写入、restart 之后有 `fleet after`；preflight/build 第一步是 `clear any earlier … gate`；build 用 `docker stop -t` 而不是 `rm -f`/`kill`，迁移后分析的对象是 `sqlite-backup` 产出的 `dryrun.post.db`。成本很低，能锁住本轮修好的顺序。
3. **"failed gate accepted" 断言是空转的**（`o0_tool.py:719-724`）：`:719` 把 `RELEASE.json` 改成候选 `d…d` 之后没有改回，`:724` 的拒绝其实来自"候选不同"，而不是 `ok:false`。变异 3j（去掉 `ok` 检查）存活就是这个原因。在 `:721` 之前把 `RELEASE.json` 恢复为候选 `c…c`。这正是"测试里绕开的那个报错"的形状：绿了，但测的已经不是它声称的那件事。
4. **site check 内嵌的 `redact_line` 没有被测试钉住**（变异 5e 存活）：parity 只比骨架。建议把 parity 扩到 `redact_line`（同一组语料：短 Bearer、basic、查询值、`KEY=VALUE`），或在 S-10 的 `ExecStart` 桩里放一个短 Bearer 哨兵（例如 `Bearer pw7short`）。
5. **restore-db 失败时没有写恢复路径**（`o0_deploy_watcher.sh:271-281`；部署 runbook W-6 的"失败处置"列）：库文件已经移到 `backup-watcher/db-replaced/`，如果新库上 watcher 起不来，脚本退出，watcher 停着。runbook 应写明手工换回的两条命令。另外 `:274` 把属主写死为 `root:root 0600`。与目前卷里的实际情况一致（记忆 09-11 条目），但更稳的做法是在移走之前 `stat` 被替换的文件，按原属主和权限装回；S-05 也补上 `.Config.User`。
6. **S-10 的隔离违例没有在阶段 O 强制**：§7 写的是"违反即阻断阶段 O"，但 `o0_deploy_operator_query.sh` 的 preflight 没有这一步。把 S-10 的同一段检查加进 `phase_preflight`，违例即失败，不写门禁。
7. **守卫阈值与事实对齐**：仓库里有 fail-closed 判定的依据。节点心跳默认间隔 2.0 秒（`services/nautilus-node/runtime/control_plane_session.py:14`）；`heartbeat_timeout_seconds` 是必填配置，示例为 15 秒（`services/nautilus-node/config/examples/account-*.sandbox.json:28`）；判定在 `app/nautilus_actors.py:4160`。所以 5 秒的年龄阈值约等于 2.5 个心跳周期，60 秒的稳定窗约为 4 倍判定时长，都合理。前提是生产配置与默认一致。建议 S-00 增加一条：读取四个节点配置里 `heartbeat_timeout_seconds` 与心跳间隔（非秘密键），`O0_FLEET_MAX_HB_AGE` 取 2.5 × 间隔，`O0_FLEET_SETTLE_S` 至少取 `heartbeat_timeout + 3 × 间隔`。
