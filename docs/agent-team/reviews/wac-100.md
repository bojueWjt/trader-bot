## 重点核查结论

- **只绑 127.0.0.1**：gateway 的 host 写死在 `gateway_launcher.py:16`、`:34`，不可配置；watcher 通过 `WATCHER_HOST=127.0.0.1`（backend.py:184 → server.js:897）。实测 LAN IP 两个端口都拒绝连接。
- **环境从零构建**：`_base_env`（backend.py:164-177）只有 PATH（node/python 所在目录 + /usr/bin:/bin）、HOME/TMPDIR（都指向 state dir）和 locale。test:261-283 设置了调用方的 `RISK_ADMIN_TOKEN`/`DATABASE_URL`/`WATCHER_ALERT_BOT_TOKEN`/`TELEGRAM_PROXY_HOST`，断言它们都不会泄漏进子进程；实测环境变量名清单与此一致。
- **不读真实 env/secret**：grep 过 scripts 里的 `environ|getenv|expanduser|/srv|.config`，没有读取点（`WAC_MANAGER_PYTHON` 只选解释器）。watcher 源码中没有 dotenv；read_api 和 app_roles 中没有 `load_dotenv`/`expanduser`。唯一的 `/srv` 常量是 read_api.py:6246 的 attribution-shadow 日志，只在 operator 开仓路径上，本地无 DB 时走不到。
- **watcher 不连 Telegram、不外发**：watcher 从 state dir 里的副本运行（backend.py:440-449、522），`config.json` 只有 `watchGroups`，没有 apiId/apiHash/session，因此 `startListening` 在 server.js:315 直接返回，启动时的自动连接（server.js:905）也不会触发。第二道保险是把 SOCKS 代理指向 127.0.0.1:9（backend.py:190-193 → telegram-proxy.js:48-53）。告警 bot token 为空，`sendWatcherAlert` 在 server.js:113 直接 return。price monitor 和 signal importer 都关闭（实测日志 `[price-monitor] Disabled`）。凭据面路由 `/api/config`、`/api/login/*` 在网关契约中是 browser_only（routes.yaml:256-258），app 经网关到不了。
- **down 只杀自己、只删自己**：进程归属按"记录的 pid + `ps lstart` 启动时间 + 命令行包含 state dir"判定，进程组成员另需 pgid 匹配加命令行包含 state dir（backend.py:326-336）。删除前要求 marker 文件是普通文件、不是 symlink，且 marker 内记录的路径等于目标路径（backend.py:96-103）。还有进程残留时保留目录不删（backend.py:380-382）。`rmtree` 对里面的 `node_modules` symlink 只做 unlink、不跟随，有测试 test:346-365 和实测两方面证据。

5. 验证命令里的 `.venv-arch/bin/python` 在 wac-100 worktree 中不存在。`find_python` 会自动回落到主 checkout 的 `.venv-arch`（backend.py:241-247），这是只读引用，没有问题；手工跑 pytest 时要用主 checkout 的 venv 路径。
