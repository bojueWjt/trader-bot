## 4. F-01 的"原始路径与解码一次各判一次、解码抛错视为命中"会不会误伤

- **browser 不受影响**：这一步只对非 browser 身份执行。站点的 `encodeURIComponent` 路径（例如 `user%40example.com`）、`/`、`/api/login/*` 行为都不变。
- **gateway 和 snapshot 的合法请求不会被误伤**：合法请求的 raw path 不含 `%`（gateway_pattern 全部不允许 `%`，网关在 G1 也会拒绝含 `%` 的 raw path），因此解码前后是同一个字符串。实测 38 个合法请求零误命中。
- **只有状态码变化，没有放行变化**：含 `%` 的请求原本就会在 W3 规范化被 404 拦下。现在其中解码后命中凭据面的请求（例如 `/api/login%2Fstart`），以及非法编码（例如 `/api/trading/accounts/%E0%A4%A`），改为 403 `identity_forbidden`。gateway 直连 `/`、`/healthz/`、`/API/CONFIG`、`/api/login` 由 404 变为 403，snapshot 身份访问凭据面也变为 403。这与 Planner 的 R17 一致。`auth-media.test.js:164-165` 的两个 404 断言（`/api/status/`、`/api/%73tatus`）不受影响。

## 5. 分级意见

### 🔴 无

### 🟡

**🟡-1（F-01，§9.2 第 5–6 步）"path 部分"没有定义，`#` 和 absolute-form 能绕过 NA，现在只靠身份路由表兜底。**
Node 会把 `/api/config#x` 和 `http://evil/api/config` 原样放进 `req.url`，而 Express 用 `parseurl` 取 pathname 后照常路由到凭据面 handler（实测 200）。`auth.js:157` 用 `req.originalUrl.split("?")[0]` 取路径，所以 NA 看到的是 `/api/config#x`，判为未命中。规范化步骤能拦下 absolute-form（含 `//`），但拦不住 `#`。今天没有造成放行，是因为身份路由表的正则锚定了整串，匹配失败后返回 404。契约宣称"这一步不依赖身份路由表"，对 `#` 不成立。

建议 wac-015b 与下次勘误二选一：(a) 在规范化中写明：非 browser 身份的请求目标不以 `/` 开头，或含 `#`、`\`，一律 404；(b) NA 同时对 `parseurl(req).pathname`（Express 实际用来路由的路径）判定一次。无论选哪种，都在 §9.14.4 第 3 项的探针里加 `/api/config#x`、`/healthz#x`、`http://x/api/config`。

**🟡-2（F-04，§9.14.4 第 1 项）用 Python 探针检查兜底正则时，结果与 RE2 不一致，"无法比较"被当成了"相等"。**
`re.search('^(?i:/m/v1/watcher)(?:/|$)', '/m/v1/watcher\n')` 为真，Go RE2 为假（已实测）。行级检查用的是 `fullmatch`，不受影响。兜底检查用 `re.search` 加 `$`，所以契约里"对本语法子集与 RE2 同义"的说法对兜底不成立。

建议：check 脚本对兜底正则的探针加一条断言"探针不含 `\n`"，或者在 Python 侧把 `$` 换成 `\Z` 再比较。同时在 §9.14.3 注明 `%0A` 结尾的请求在 Caddy 上不会命中兜底，会落到站点的其他处理器；这不影响安全，由网关 raw path 规则返回 404。

**🟡-3（F-04，§9.14.3 O-0 并入规则）"在站点顶层 import" 不足以保证 snippet 先于站点已有的 `handle /m…` 求值。**
Caddy v2.10.2 的 `sortRoutes`（`httpcaddyfile/directives.go:443-530`）规则如下：同为 `handle` 指令时，只有两边都是单路径匹配器才按路径长度排序；否则两边只要都有匹配器，就按出现顺序稳定排序（`:517`）。`handle_path` 整体排在 `handle` 之后。所以如果站点里有 `handle /m/*` 且它写在 import 之前，snippet 里的 `handle @wgw_*` 和兜底会被整体遮蔽，而契约要求的"兜底在这些处理器之后求值"这一检查仍然会通过。

这不是安全洞（网关仍是精确边界），但会让 Caddy 粗筛静默失效。建议：O-0 并入规则写明 import 必须位于该站点所有 `handle` 之前，或者整体包进 `route` 块；核对脚本改为检查 adapt 后站点路由链中，wgw 路由之前没有任何路由能匹配 `/m/v1/watcher*`；本机 Caddy 探针必须使用生产 Caddyfile 的副本。本条建议写入 O-0/Release 清单，也可以随下次勘误补上。

**🟡-4（F-07，R11）加载期断言要接到同一条停用路径上。**
`watcher_gateway.py:21-28` 只捕获了 import 异常。NA 的加载期断言（never_allowed 形状、NA_intersects）失败时，也必须设置 `_LOAD_ERROR`，让 `/v1/watcher/*` 一律返回 503 `gateway_disabled`，不能抛出到 `create_app` 导致进程退出。§9.14.4 第 2 项的合成行注入测试正是用来锁定这一点的。
