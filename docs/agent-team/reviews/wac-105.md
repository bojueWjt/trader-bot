## 3. 分级意见

### 🔴 Blocker

### 🟡 建议

**🟡-1（O0-A08 硬前置）在 systemd ≥ 255 上，`enable --no-reload`/`disable --no-reload` 会让整机所有单元的 NeedDaemonReload 都变成 yes。结果是 apply 成功之后 verify 必然失败，回滚总是停在 `DAEMON_RELOAD_PENDING`，G-35 这道门从此"无法比较"。**

- 位置：
  - `scripts/ops/o0/o0_deploy_watcher_gateway.sh:241-247`：apply 先 `daemon-reload`，后 `enable --no-reload`；
  - `:151`、`:157-166`：回滚先 `disable --no-reload`，再跑 reload 门；
  - `o0_tool.py:732`：cp-isolation 在 NeedDaemonReload≠no 时判 UNCOMPARABLE；
  - 测试桩 `tests/apply_rollback_test.sh:245-252`：只按单个单元模拟 NeedDaemonReload。
- 证据（systemd 公开源码，本机只读取回）：
  - v255 的 `src/core/unit.c:3915`：`unit_need_daemon_reload()` 第一行就是 `if (u->manager->unit_file_state_outdated) return true;`；
  - `src/core/dbus-manager.c:2524` 等 6 处：Enable/Disable 等 unit-file 方法在 `n_changes > 0` 时把这个 manager 级标志置真；
  - `manager.c:3586`：只有 daemon-reload 会清零它；
  - `manager.h:293-297` 的注释写明了这个用意；
  - v249、v252、v253、v254 都没有这段逻辑，v255、v256 有。Ubuntu 24.04 带 255，Debian 13 带 257。jp-24 的发行版与 systemd 版本在仓库里没有记录。
- 后果：
  - apply 在第 7 步 reload 之后才做 `enable --no-reload`。从这一刻起，全机每个单元的 NeedDaemonReload 都是 yes。apply 本身不再检查这个属性，所以会"成功"。
  - 随后 verify 的 `isolation 0`（:260）会拿到 `CP_ISOLATION_UNCOMPARABLE … NeedDaemonReload=yes`，O-3 永远拿不到 `WGW_VERIFY_OK`。
  - 任何回滚（手动或自动）做完 `disable --no-reload` 之后，reload 门看到的都是全 yes，所以总是 `DAEMON_RELOAD_PENDING`，单元文件留在盘上，`rollback_rc=1`。好在暴露已经撤掉，方向安全。
  - 更要紧的是，这时用户按 O0-A08R 决定"是否 reload"，但已经**无法分辨**有没有别的单元真的待加载，而 wac-060 与 G-35 要防的正是这种情况。
  - 沙箱桩不模拟这个 manager 级标志，所以 161 项全绿并没有覆盖到这里。
- 修法（小改，不改变任何安全方向）：
  1. apply：`reload_check`（只排除新单元）→ `systemctl enable --no-reload` → **紧接着**唯一一次 `daemon-reload`（它同时加载新单元与 wants 链接，并清掉标志）→ `units_unchanged` → `start`。随后加一条 `reload_check apply-after`，要求全部为 no，证明标志已清。
  2. rollback：先**记录**一次全量 NeedDaemonReload 快照（只记录，不作门槛）→ stop、`disable --no-reload`、删 env 与目录 → reload 门改用"disable 之前那份快照（排除新单元）"来判定。快照干净就删单元文件并 reload，然后再核对一次全部为 no；快照不干净才报 `DAEMON_RELOAD_PENDING`。
  3. 测试桩加一个"manager 已过期"的开关：任何带改动的 `enable/disable --no-reload` 之后，所有单元都报 yes，直到 `daemon-reload`。WB/WC 按这个语义重跑，并补一个用例："apply 成功后，verify 的 isolation 通过"。
  4. 现场核对 S-01 增加只读的 `systemctl --version`（首行），在 PC-6 里记录。
