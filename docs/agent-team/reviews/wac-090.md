## 7. 🟡 建议（按阻断的授权排序；都挡 O0-A05P 与 O0-A05，不挡合并）

1. **`path` 模式里的非 ASCII 字符（`o0_caddy_watcher_routes.py:514`、`:545`、`:557`）**。Python 的 `str.lower()` 与 Go 的 `strings.ToLower` 在 `İ` 上结果不同，n07 能通过 verify 并注入 observer token（本工具的探针能抓住）。修法：模式里有非 ASCII 字符时，`_caddy_path_match` 抛 `Uncomparable`（遮蔽第 1 步算命中）；或者逐码点使用简单小写映射。补 selftest 钉子（`tradİng`），`caddy_real_test` 加 n07。同时修正 runbook §3.1:86 的"18 万组 0 不一致"：应写明只覆盖 ASCII。
2. **含 `//` 的 `path` 模式（`:507-530`）**。Caddy 只在模式不含 `//` 时合并请求路径里的斜杠，而网关行用的 `path_regexp` 永远先 clean。所以 `/m//v1/watcher/<行>` 这类请求能到达网关，却不在任何固定探针里。n08 **verify 和探针都通过**，并注入 observer token；与 wac-088 §2.3 同类。修法：模式含 `//` 时抛 `Uncomparable`，算命中。探针对每条表内路径另外发一组在不同位置加 `//` 的请求（至少 `/m//v1/…`、`/m/v1//watcher/…`），都带假 Authorization，期望 clean 之后转发、并且 Authorization 原样到达。
3. **`host` 匹配器的模拟（`:564-570`，由 `:828-830` 调用，这是 wac-060 的旧代码）**。Caddy 的 `*` 可以出现在任意一个标签上（按标签数逐段比较），`{占位符}` 会按请求替换；工具只认前导 `*.`，占位符按字面比较，所以都判成不命中。n17b（`jp-bot.*.wang`）**verify 和探针都通过**，因为探针把站点改成了 `127.0.0.1`。修法：
   - 主机模式含 `{`/`}`，或者 `*` 不在首标签，就抛 `Uncomparable`（算命中）；前导 `*.` 改成按标签数判定。
   - 探针保留真实站点名：站点地址写成 `http://<site-address>:<端口>`，加 `bind 127.0.0.1`，每个请求带 `Host: <site-address>`。这样依赖 host 的路由在探针里的行为与生产一致。
   - runbook U-6 的审阅要点加上"匹配器里有非 ASCII 字符、`//`、host 里有 `*` 或 `{`"。
4. **探针的清理（`:1858-1873`，`:1647-1648`）**。实测 Ctrl-C 落在 `finally` 里 `stub.close()` 的等待期间（三个桩最长约 1.5 秒），或者进程收到 SIGTERM，都会留下含 bcrypt 哈希的 `.o0probe`（0600）和临时目录。修法：
   - `finally` 里先 `unlink` `.o0probe`、`rmtree` 临时目录，再停 Caddy 和桩；桩只调用 `server_close()`，或者给 `shutdown` 设超时。
   - 为 SIGTERM/SIGHUP 装处理器，转成 `SystemExit`。
   - 文档里"任何结局下都删除"改成如实描述，并保留 runbook 里"完成后 `ls -A` 确认"这一步。
5. **测试缺口（质量项，建议与 1–4 同批）**：
   - 让 preflight 在沙箱里真正执行一次（stub `caddy`），覆盖 `CANDIDATE_IN_STAGING`、`PROBE_BINDING_OK/FAILED`、线上片段比对。这样能抓住 R13、R16、G29、G30。
   - 断言检查失败的探针也清理了 `.o0probe`（R06）。
   - `assert_probe_pinned` 加一个 listen 为 `0.0.0.0` 的负例（R05）。
   - 用打桩的 `Path.exists` 测试 jp-24 拒绝（R12）。
   - 设 `HTTP_PROXY` 跑一次探针，断言 Caddy 进程拿不到代理变量（R10）。
