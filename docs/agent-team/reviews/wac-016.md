## 3. 🔴 Blocker

**🔴-1 全量测试回归：对 ALL 角色调用 `create_app` 会修改共享的全局 app，app 启动后再调用就会抛 RuntimeError。**
- 位置：`read_api.py:10595-10596`、`watcher_gateway.py:493-494`。
- 原因：角色为 `AppRole.ALL` 时，`build_role_app` 直接返回全局的 `all_role_app`（`app_roles.py:150-151`），`create_app` 随后对它执行 `add_middleware`。模块在 import 时已经调用过一次 `create_app()`（`read_api.py:10607`），之后每调用一次 `create_app(ALL)` 就会多叠一层中间件。只要这个全局 app 服务过请求（全量测试里前面的用例就会触发），Starlette 就会抛出 `RuntimeError: Cannot add middleware after an application has started`。单独跑这个用例能通过，全量跑就失败（`tests/control-plane/api` 子集实测：562 passed，1 failed）。
- 生产影响：每个进程只在 import 时调用一次，所以当前不会触发。但这属于红线 7（原先通过的测试现在失败），`install_middleware` 也不是幂等的。
- 修法：在 `:10584` 旁边、`register_routes(app)` 之后，对 `all_role_app` 只安装一次中间件；`create_app` 里只对 `role_app is not all_role_app` 的 operator-query 角色安装；`install_middleware` 先检查 `app.user_middleware` 中是否已有 `GatewayPathMiddleware`。修完后按全量测试验收：783 passed，5 个预存失败。

**🔴-2 生成物以 `phase_max=P3` 提交，注册了契约写明"当前生成物不注册"的 P3 行，A-6 的授权缺口因此暴露。**
- 位置：两份生成物的 `_meta.phase_max = "P3"`；测试把这个值写死了：`test_watcher_gateway.py:69`、`:248`（24 行）、`gateway-routes-generated.test.js:9-11`（`'P3'`、24、63）。
- 契约：§9.15 的召回待办写的是"`gw.price_alert.delete` 只带 `client_ref`，app 可以按 id 删掉站点创建的 `source=watcher` 提醒……P3 受 `phase_max` 门控，**当前生成物不注册这些行**，因此不阻塞 P0–P2"。
- 实测：在真实的 `create_app("operator-query")` 上，`DELETE /v1/watcher/price-alerts/1` 带 risk_admin 凭据会被转发到上游。集成分支里已经合入的 W-0a 手写路由表（`watcher-routes.js:161-164`）对 gateway 身份放行了这条路由。两边合起来，就是 A-6 描述的"按 id 删掉任意提醒"。部署门禁会核对 `phase_max`，但集成分支上的产物本身就违背了契约。属于红线 5。
- 修法：用 `--phase-max P2` 或更低重新生成，具体值由 Planner 裁定；测试里的期望行数改为从 `PAYLOAD["_meta"]["phase_max"]` 和 payload 推导，不再写死 24/63/P3。

**🔴-3 媒体行的上游错误体透传会产生不合法的 HTTP 响应：`Content-Length` 与 body 不一致。**
- 位置：`watcher_gateway.py:405`、`:409-412`。
- 原因：媒体行在上游返回非 200/206 时走 `_json`。`_json` 用该行的 `media` 头白名单复制上游头，白名单里有 `Content-Length`，而 body 已经被网关重新序列化过（加了 `request_id`、过滤了 `message`）。Starlette 在头里已有 `content-length` 时不会重算。
- 实测：在真实的 operator-query 角色 app 上，上游返回 416 时，网关响应头是 `content-length: 49`，body 实际是 93 字节。用 h11 服务端复现，得到 `LocalProtocolError: Too much data for declared Content-Length`，也就是说在 uvicorn 下连接会被中断。
- 受影响的有：缺图 404 `not_found`（最常见的媒体错误）、416 `range_not_satisfiable`、A-3 透传的 503 `media_too_large`，以及媒体行上的 400/409。§9.6 和 §9.9 规定的行为实际上交付不了。属于红线 5。
- 修法：`_json` 不复制 `Content-Length`，由 `JSONResponse` 重新计算；416 的 `Content-Range: bytes */<size>` 按 §9.9 保留。新增测试：对每类网关响应断言 `int(content-length) == len(body)`。

**🔴-4 覆盖不足：任务书验收清单中有 5 组安全相关条目没有测试，变异实验证实这些位置的回归抓不住（见第 5 节）。**
1. **R10 非 ASCII 键被拒**（M6 漏过）：现有探针 `apı_key`、`apİ_key` 本身就会被 Python 的 IGNORECASE 正则命中，所以删掉 `isascii` 判定后测试照样是绿的。需要补一个正则完全不命中的非 ASCII 键，例如 `näme`、`ключ`，在请求 body 和响应嵌套键里各测一次。
2. **G5 `gateway_disabled`**（M13、M14 漏过）：缺 `WATCHER_GATEWAY_TOKEN`，或它与控制面 token 目录撞值，都应返回 503 `gateway_disabled`，对应计划 §4.2"operator-query 缺 gateway 时只禁用网关"和契约 §9.2。我用探针确认实现是对的，但没有测试锁住。
3. **R3 顺序：鉴权先于准入**（M2a 漏过）：把准入挪到鉴权之前，8 个用例仍然全绿。需要补两条：槽已满时无 token 请求返回 401 而不是 503；槽已满时 viewer 调写行返回 403。
4. **身份映射**：signal token 应得 403 `insufficient_scope`，`TokenCatalogError` 应得 503 `auth_unavailable`（红线 3 的鉴权边界）。探针确认实现正确，但没有测试。
5. **上游映射与 R8 形状**：只测了 503 `db_busy` 和 401。以下都没测：400 `invalid_actor_headers`、404 `route_not_found`、403、500，以及不在白名单内的 503，都应映射为 503；A-3 的 503 `media_too_large` 应透传；错误体里的 `error` 和多余键应删除；`message` 超长或含控制字符时应替换为 code；缺 `code` 或 code 格式不合法时应得到 `malformed_response`。探针确认实现正确。

另外，JS 生成物的摘要自检（M8c）也没有测试锁住，放在 🟡-6。

## 6. 🟡 建议

1. **JSON 行会发出两条 Cache-Control 头**（`watcher_gateway.py:405-406`）。`_response_headers` 返回小写键 `cache-control`（上游值），随后又写入大写键 `Cache-Control: no-store`，结果两条头都发出去了。实测上游带 `public, max-age=600` 时，客户端收到两条。媒体路径用的是小写键覆盖（`:436`），没有这个问题。
2. **query 整数超过 4300 位时出现未捕获的 ValueError**（`:234-236`）。`int(value)` 抛异常，客户端拿到 500 纯文本，不是契约要求的 400 `invalid_query`。建议把正则收紧为 `[0-9]{1,18}`。
3. **G5 缺 token 或撞值时没有告警日志**（`:302-308`）。§9.2 要求"打告警日志"，而且只写变量名。
4. **S-10 用的是写死的 `SECRET_FIELDS`**（`watcher_gateway_routes_lib.py:21`、`:170-171`），没有读 YAML 的 `secret_fields`，M15r 因此漏过。运行时会用 payload 里的 `secret_fields` 拒绝，所以目前没有安全缺口，但校验比规格弱。建议改为 `set(data["secret_fields"]) <= deny`，写死的集合留作额外的下限预言。
5. **第三份生成物 `contracts/generated/caddy-watcher-gateway-paths.txt` 没有生成**。§9.14.3 和 §9.14.4 第 1 项写的是"三份"，任务书收窄成了两份，不算执行者的问题。O-0 核对 Caddy 时依赖这份清单，请 Planner 另开任务或出勘误。
6. **node 测试没有锁住 JS 摘要自检**（M8c 漏过）。建议加一个篡改 `_TEXT` 后 `require` 必须抛错的用例（在临时目录里操作）。
7. **§9.14.4 第 2 项的运行时集合相等只在裸 FastAPI 上做了**（`:67-73`）。在 `create_app("operator-query")` 上只断言了数量（`:248`）。建议把 `{(method, path, name)}` 集合相等、`iscoroutinefunction`、`body_params`、`body_field` 这几项断言挪到 operator-query 角色 app 上。
