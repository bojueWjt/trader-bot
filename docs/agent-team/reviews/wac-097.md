## 2. 核实要点逐条

### 2.1 遮蔽第 1 步的三种放行条件（item 1）

- **常量 `uri`**（`_constant_path`、`_uri_path_part`）：路径部分为空时不作为证明；含 `%`、占位符、glob 字符、`#`、`?`、`//`、点段、空白或非 ASCII 的都不作为证明；比较时统一转成小写。结论：只在能证明时放行。B3（`rewrite @s /m/v1/watcher;a`）放行正确，真实 Caddy 上没有到达任何桩。
- **`strip_prefix`**（`_strip_prefix_paths`）：我自己推导了一遍。Caddy 先对未解码路径做 clean，再按解码后的字符逐个剪掉 P。所以结果等于 clean(剩余部分)，也就是"匹配时看到的路径 Q 去掉 P 的某一段前缀"：弹出次数不少于 k 时什么也不去掉，否则去掉 P 的前 k−j 段。P 在段中间结束时，剩余部分没有前导 `/`，工具补上 `/` 再判，结果只会更保守。工具实现与这个推导一致。差分：772 个"证明在外"的用例、348,184 次请求，0 危险。另外：B2（P 比模式更长）、B5（P 大小写混写加编码点段）判失败，真实 Caddy 确实会注入；B4、B6 判通过，真实 Caddy 没有注入。
- **`strip_suffix`**（`_strip_suffix_safe` 加 `_item_may_start_prefix`）：后缀不含 `%`，也不会是只有点的串，所以剪掉后缀之后，结果总是 Q 的一个字符串前缀。唯一的例外是多弹出一段，而那只会让结果更短。Q 本身不以前缀开头时，它的任何前缀也不会以前缀开头。结论：只在能证明时放行。B1 在真实 Caddy 上没有落进空间。
- **`handle_path` 转发 8183 一律失败**：在没有内层匹配器时成立（P3、g18、`handle-path-to-oq-plain`），与契约 §9.14.3 并入规则的方向一致（"不得有其他处理器把前缀转发到 operator-query"），也与 R22 白名单一致（链上有改写的转发器不在白名单里）。**但带内层匹配器时不成立，见 🔴-1**。文档里"`handle_path … { reverse_proxy <8183> }` 一律失败"的说法（`o0-authorization-list.md:11`、`o0-requirements.md:552`）因此不准确。

### 2.2 正则扫描器与 `_re2_compile`（item 2）

- 以 `]` 开头的字符类（`[]…]`、`[^]…]`）：扫描器与 `_re2_compile` 的规则一致，也与 Go 一致。
- POSIX 类（`[[:alpha:]]`）：扫描器按 Go 处理，`_re2_compile` 不认 POSIX 类，两者**不一致**。后者被 Python 编译成 `[[:alph]` 加一个字面的 `]`，还会在 stderr 打出 `FutureWarning: Possible nested set`（re54 复跑时就出现了）。我没有找到能利用它的写法：命中空间的判定由扫描器兜底，watcher 路由有"没被样本覆盖即失败"的检查。见 🟢-1。
- `\Q…\E`：Python 编译不了 `\Q`，会抛 Uncomparable，按命中处理，这是保守的。扫描器按 Go 处理。但 `\Q\E` 为空、后面紧跟量词时，函数层面会漏判，见 🟢-2。
- 差分（`r099/rediff.py` 加 Go 判定器，`rediff-branch.txt`）：种子 1–5，每个种子 4 万个模式，只有 1 个漏判（`^/m/v1//\Q\E*[^/]+/`），而且整条 verify 能抓住它。

### 2.3 转发链的容器枚举（item 3）

- subroute、`reverse_proxy.handle_response`、`invoke` 到 `named_routes`、`errors.routes`：都跟进了。C2、C3、C5、E1、q1–q4 在真实 Caddy 上都判失败。
- **未知容器并不总是判 UNCOMPARABLE**。`_forwarder_check` 只在该路由的匹配器可能命中 `/m` 前缀时，才会走到未知容器的分支（`:1635` 先 `continue`，走不到 `:1673`）；`_rewrite_forwarder_check` 只在"已改过路径"时才判它（`:1745` 条件里有 `and changed`）。所以 `handle /x/* { intercept { handle_response { … } } }` 被整个跳过了，见 🔴-2。

## 6. 🔴 Blocker

### 🔴-1 改路径之后再出现匹配器，改路径转发检查就不再判定；A7、A8 的 verify 与探针都通过，真实 Caddy 会把匿名请求带着 observer token 送进 `/v1/watcher/*`

- **位置**：`scripts/ops/o0/o0_caddy_watcher_routes.py:1757`。`walk(r.get("handle") or [], inner, False if constrained else cur_changed, …)`：一条路由有匹配器时，就把"已改过路径"清零，此后的 `reverse_proxy` 因为 `sent_changed` 为假而被跳过（`:1728-1731`）。
- **为什么会漏**：文档字符串 `:1691` 说"改路径之后再次被匹配器约束的路径，交给看得见该匹配器的 `_forwarder_check` 判定"，这句话不成立：
  - `_forwarder_check` 只用 `/m` 前缀的探针（`PREFIX_PROBES`）判定，并且只看"为 `/m` 前缀写的"模式，根本不判 operator-query 的 `/v1/watcher` 空间；
