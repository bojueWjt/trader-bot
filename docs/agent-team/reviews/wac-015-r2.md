## 6. 💭 Nit

1. 变异 M12c（摘要忽略 body）现在会让整个 node 测试集**挂起**，而不是失败：`reentrant-write.test.js:74-96` 的在途冲突测试在回归后，第二个请求会并入一个永远不会 release 的在途 promise。它仍然算被抓住（我用 240 s 超时判定），但在 CI 里表现为卡死，比明确失败难排查。建议给该测试加 `{ timeout: 5000 }`，或者用 `Promise.race` 包一层，并在 `finally` 中调用 `release?.()`。
2. `db_manager.py` 的 CLI 前置拦截可以被 `--` 绕过（`db_manager.py --db x -- set-risk BTCUSDT 0.5`）。这时请求会落到类方法的 `RuntimeError`，以 exit 1 加 traceback 结束。我实测没有写入，traceback 也不含参数值，所以不算缺口。可以在 `parse_args()` 之后再用 `args.command in disabled` 判一次，统一成 exit 2。
3. `request-validation.js:201` 的 `overrides[key]` 会沿原型链查找。当前 allow 列表中不可能出现 `constructor` 之类的键，所以无害；改用 `Object.hasOwn(overrides, key)` 更稳。另外，变异 M23b（改回写死 override）存活，因为测试只能证明"结果与生成物一致"，证明不了"数据来自生成物"。在生成物只有这一条 override 的前提下，可以接受。
4. `startup-failure.test.js:50-71` 用 vm 加伪造 `process` 运行 trading-api 源码，与模块的真实加载方式不同。以后 trading-api 如果在顶层读 `process.*` 的其他字段，这条测试会意外失败。目前没有问题。
