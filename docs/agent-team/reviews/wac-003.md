## 🟡 建议（不阻塞，建议在 A-T 前或作为跟进项处理）

1. **守卫漏掉换种写法的断点**：`__tests__/tabletSourceGuard.test.ts:24`。正则只匹配字面量 600 和 840，所以 `> 599`、`>= 839` 这类等价断点能通过（变异已证实）。T7A-2 的原文是"硬编码断点数字"，599 和 839 就是换了一种写法的同一个断点。建议把 599 和 839 也加进匹配。
2. **守卫漏掉 `Dimensions` 的其他访问方式和散落的阈值**：`__tests__/tabletSourceGuard.test.ts:21`。`Dimensions['get'](...)` 和解构写法 `const {get} = Dimensions` 都能绕过；更要紧的是 §7A.1 禁止"自写阈值"，但组件里可以直接用 `useWindowDimensions().width >= 700`（变异已证实）。建议再加一条守卫：`useWindowDimensions` 只允许出现在 `ui/useLayoutClass.ts` 和 `ui/BottomSheet.tsx`（取高度）里，这正好对应计划写的"除 useLayoutClass 与 BottomSheet 高度外"的豁免。两处现有代码都合规（已 grep 核对）。
3. **键盘避让用例的前提说法不准，不能算作覆盖了 T7A-5 的"键盘避让（横屏）"**：`__tests__/bottomSheet.test.tsx:100-102`。注释说"Android 键盘打开时窗口变小，maxHeight 必须跟着变小"。但按 RN Android 的已知行为，键盘弹出时 `Dimensions` 的 window 尺寸并不会变；RN `Modal`（Dialog）的避让是靠 adjustResize 缩小内容视图、再由 `root` 的 `flex: 1` 加 `justifyContent: 'flex-end'` 完成的。这个用例实际测的是"窗口高度变化后重新计算 88% 上限"，这件事本身有价值，但它不是键盘避让。建议改注释和用例名，并在看板上把 T7A-5 的键盘项标为"待 Tester 在 Xiaomi Pad 横屏真机验收"（§7A.2 已有这条），不要让它被当成已由单测覆盖。附带一个风险：`styles.sheet` 默认 `flexShrink: 0`，横屏开键盘后可用高度小于 88% 窗口高时，抽屉可能顶出上沿。这是改动前就存在的行为，不属于本任务，交给 Tester 在真机上确认。
4. **"保持当前 Tab"没有被直接断言**：`__tests__/tabletNavigation.test.tsx:69-78`。整个用例都停在初始 Tab（Home）上，所以"档位切换后 Tab 被重置回初始"这种回归只有在它同时导致 Home 重挂载时才会被抓到。建议先切到 `tab-trading`，再改宽度，然后断言焦点仍在 Trading，并且 Trading 的挂载计数仍为 1。
5. **宽屏下的安全区没有断言**：`__tests__/bottomSheet.test.tsx:92`。`paddingBottom > 24` 只在 compact（宽 400）下检查了一次；T7A-5 要求三档都覆盖安全区。建议在宽度循环里也断言一次。

## 💭 nit

1. `__tests__/tabletNavigation.test.tsx:58`：`parseAttentionLink` 是纯函数，和布局无关，放在宽度循环里每次结果都一样，是一条恒真断言。`linking.ts` 本次没有改动，所以不影响结论；以后如果要真的验证"深链在三档下一致"，应该通过 NavigationContainer 的 linking 配置在宽屏下导航一次。
2. `__tests__/tabletNavigation.test.tsx:64`：`assertPosition` 断言的是传给 Navigator 的 prop，而不是渲染结果（比如容器的 `flexDirection: 'row'`）。变异 M9 能被杀死，所以够用了。
3. `__tests__/tabletSourceGuard.test.ts:4`：`path.resolve('src')` 依赖 cwd 是 app 目录（`npm --prefix` 能保证）；如果从仓库根直接跑 jest 会扫错目录。建议改成 `path.resolve(__dirname, '../src')`。另外三个测试都没有把 `Dimensions.set` 的恢复放进 `finally` 或 `afterEach`（`bottomSheet.test.tsx:104` 等），断言一失败就会把改过的尺寸泄漏给同一文件里后面的用例。
4. `src/navigation/RootTabs.tsx:131`：侧栏模式下 `tabBarStyle.borderTopColor` 不起作用，侧栏分隔线会用导航主题的默认颜色。这是纯视觉问题，留给 A-T 或真机截图时再看。

## 表扬

- `useLayoutClass` 对非有限宽度 fail-safe 回 compact，而且导出了阈值常量，测试先锁住了 600 和 840 本身，再测 599/600/839/840 与 undefined 的序列，并且逐次断言每次尺寸变化恰好触发一次重算。
- 不重挂载用的是挂载 effect 计数，而不是渲染次数，这正是"不重挂载"该用的判据，强制加 `key` 的变异也能被它抓住。
- 五个屏幕都只包了一层外壳，没有碰内部布局；把 `contentContainerStyle` 挪到内层之前，确实需要先确认没有 `flexGrow`，而这个前提成立。
