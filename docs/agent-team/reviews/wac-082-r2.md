## 5. 分级意见

### 🟡-1（预存问题，不是本次 diff 引入；建议另开任务）：`missing` 方向没有失败用例，而且 `sameShape` 把 Express 5 的花括号语法当成契约模板参数，判为相等

位置：`scripts/dump-route-table.js:69-79`（`sameShape`）、`:81-86`（`missing`）。

**问题在哪**
- 契约模板用 `{alert_id}` 表示参数。在 Express 5（path-to-regexp 8.3.0）里，`{…}` 是**可选组**，`{alert_id}` 表示一段字面文本 `alert_id`。
- `sameShape` 只把 `:x` 认作参数段，其他段逐字比较，于是 handler 段 `{alert_id}` 与模板段 `{alert_id}` 被判为相等。
- 这是两种记法碰巧写成了同一串字符，属于"无法比较"被当成"相等"。

**实测**
- 在 `lib/trading-api.js:473` 把 `app.delete("/api/price-alerts/:id"` 改为 `app.delete("/api/price-alerts/{alert_id}"`：
  - 分支脚本 exit 0，`missing=[]`；integ 版脚本同样 exit 0，说明是预存问题；
  - watcher 全量 153 条测试全绿（变异 D22 存活）。
- 用同一个 Express 实测该路由：`DELETE /api/price-alerts/123` 返回 404，`DELETE /api/price-alerts/alert_id` 返回 200。
- 结论：§9.14.4 第 3 项要求"每条 payload inner 路由都有 handler"，这条路由在运行时并不存在，校验却判定它存在。

**为什么不判 🔴**
- `sameShape` 的逐段比较逻辑自 integ 起就没有改过，本次 diff 没有碰它。
- 本轮任务范围（wac-084）是 `unexpected` 方向与崩溃退出，不包括这一点。
- 这是 fail-safe 方向：结果是路由缺失、返回 404，不会暴露端点。
- 合并后 integ 只会比现在更好，扣住这个分支并不能让 integ 更安全。
- 这一条第 1 轮我就应该报出来，是我漏了。

**修复建议**
1. 在 `sameShape` 中，非参数段只要含有 `{ } * ( ) ? + ! \\` 或非整段的 `:`，就直接返回 `false`，按"不可比较"处理，不做逐字比较。
2. 补 `missing` 方向的失败用例，每条都断言 `status === 1`，并断言 `missing` 中精确出现对应的行：
   - 摘掉一个合法路由（覆盖 D16）；
   - 摘掉 static、media 或 validation 挂载中的一个（覆盖 D15）；
   - 用 `/:a/status` 替换 `/api/status`（覆盖 D18）；
   - 用 `["/api/status"]` 替换（覆盖 D19）；
   - 用 `/api/price-alerts/{alert_id}` 替换（覆盖 D22）。
   - 注入钩子需要挂在脚本调用 `registerTradingApi` **之后**，写法见 `r085/inject085b.js` 的 `after()`；否则 trading-api 的路由还没注册，`findIndex` 返回 -1，`splice(-1, 1)` 会删错 layer。
3. 另外建议补一条 HTTP 级测试：带真实 id 调用 `DELETE /api/price-alerts/:id`。D22 能在全量测试中存活，说明目前没有端到端用例覆盖这个路由。
