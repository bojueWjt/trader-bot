## 4. 真实性核对

- **W10 的见证点**：`/api/trading/accounts/acct-1%23x` 走 gateway 身份。有 `%` 规则时返回 404，删掉 `%` 规则后返回 403。这是上轮模糊对照发现的那个分歧点，所以这条测试确实锁住了第 6 步本身，而不是被第 7 步兜住。
- **非 ASCII 用例**：绕过 llhttp，直接用伪造的 `req` 调用中间件，对两种身份各测 5 个字符，并断言 `next` 没有被调用。
- **加载期负例**：6 种篡改，同时断言 `assertPayload` 和 `createAuthMiddleware(TOKENS, source)` 都会抛错。报错正则与 `auth.js:150-174` 中各分支的报错消息一一对应。
- **停用日志**：四个角色的 token 用 `monkeypatch.setenv` 写入环境，探测请求带 `Authorization`。这样"日志不含 token"的断言确实可能失败（G16 被抓住就是证明）。另外新增了"日志不含 `Authorization`"的断言。
- **S-xx 篡改用例**：每处替换都先断言 `count(old) == 1`，所以替换不会静默落空。同时断言退出码为 1、输出中含对应的检查号、输出中不含 `ROUTES_DIFF_EMPTY`。

### 🟡

**🟡-1 `scripts/dump-route-table.js:21-28`、`:65-70` 的收紧仍有绕过形式（不作为 FAIL 理由：比原来严格，而且真正的防线是鉴权中间件）。**

我用与仓库测试相同的 preload 注入方式，在分支上逐一实测。下面这些注册方式，脚本都以 exit 0 通过，`unexpected=[]`：

| 注入 | 为什么漏掉 |
|---|---|
| `app.use("/api", fn)` | 挂载检查用的是 `startsWith("/api/")`，没有覆盖正好等于 `/api` 或 `/media` 的挂载点 |
| `app.use("/media", fn)`（非 `mediaHandler`） | 同上 |
| `app.use("/API/x", fn)`、`app.post("/API/rogue")`、`app.post("/Api/Rogue")` | Express 5 默认路由不区分大小写，但这里的比较区分大小写。`:65` 的 handler 过滤是预存问题，这次没有加剧 |
| `app.use(["/api/x"], fn)`、`app.use(/^\/api\/x/, fn)` | 路径不是字符串时，一律按 `/` 记录 |
| `app.use(router)`，而 `router.post("/api/rogue")` 写在子路由里 | 没有递归进入 `layer.handle.stack`（预存问题） |
| `app.use("/api/x", function mediaHandler(){})` | 按函数名豁免，可以被冒名 |

现实影响：鉴权中间件先执行，表外路径到不了这些 handler。但如果有人在 `server.js` 的路由之前挂 `app.use("/api", fn)`，就能改写已放行路径的行为，而 §9.14.4 第 3 项的 diff 判定对此没有反应。

建议（下次触及这个脚本时一并处理，可以不单独开任务）：
- 挂载点按白名单判定：根路径只允许已知名字（`watcherAuth`、校验中间件、`serveStatic` 等），`/media` 只允许 `mediaHandler`，其余一律算 `unexpected`；
- 比较前先转小写；
- 路径不是字符串时直接算 `unexpected`；
- 递归枚举子路由；
- 测试中把上表的形式各注入一次。

**🟡-2 `tests/control-plane/api/test_watcher_gateway.py:477-478`：四来源停用测试不再覆盖"不带认证"的请求。**

- 原来的两条探测不带认证头，现在改成了带认证头，所以"不带认证 × 四种停用来源"这一组合没有测试了。
- 目前靠 `test_missing_artifact_only_disables_gateway:593`（只有 `PAYLOAD=None` 一种来源，不带认证）兜底，G06 仍然被抓住，但失败数从 2 降到了 1。
