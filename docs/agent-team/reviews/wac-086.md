### 🟡-1（预存问题，fail-safe，不阻塞）：`sameShape` 用 Unicode `toLowerCase` 做比较，并默认路由大小写不敏感，仍有"不可比较被当成相等"的漏口

位置：`scripts/dump-route-table.js:73-80`。

**问题在哪**
- 本次修复在第 80 行加了黑名单 `[{}*()?+!\\:]`，但比较前第 73-74 行做的是 Unicode 小写化。
- `"K".toLowerCase() === "k"`（KELVIN SIGN），所以 handler 段 `risKs` 与模板段 `risks` 被判为相等（M12）。
- 运行时这个路由匹配不到任何 ASCII 请求，返回 404。
- 同样，第 73-74 行的比较默认 Express 不区分大小写。如果启用 `case sensitive routing`，大写的注册（M13）在运行时同样是 404，脚本却判定存在。

**为什么不判 🔴**
- 小写化比较在 integ 里就已存在，不是本次 diff 引入的。
- 方向是 fail-safe：结果是路由缺失、返回 404，不会暴露端点。
- 两种写法都很刻意，不是正常开发会写出的源码。
- 合并后 integ 严格比现在更好。

**修复建议**
1. 把第 80 行的黑名单改成白名单：用原始（未小写化的）段做判断，只接受 `/^[A-Za-z0-9._-]+$/u`，并按 ASCII 做大小写折叠。这样同一处代码也能关闭 💭-1。
2. 在脚本中断言 `!app.enabled("case sensitive routing") && !app.enabled("strict routing")`，不满足就报 unexpected 或直接失败。另一种做法是启用大小写敏感时改为逐字比较。
3. 补两条用例：M12（KELVIN SIGN）和 M13（启用大小写敏感路由）。

### 🟡-2（测试区分力不足）：HTTP 删除测试只有一行数据，分不清"按 id 删除"和"删除全部"

位置：`__tests__/gateway-http.test.js:79-89`。

**问题在哪**
- 变异 H2 把删除语句改成 `DELETE … WHERE order_id = ? OR 1`，会清空整张 `price_alerts` 表，但测试照样是绿的。
- 原因是库里只有这一行，而测试只断言"这个 id 已经不存在"。

**修复建议**
- 先建两条提醒，删除其中一条。
- 然后断言被删的那条计数为 0、另一条计数为 1。

这是一处很小的补充，但它把"删对了"从假设变成了断言。
