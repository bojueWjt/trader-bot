# Q3–Q5 量化工具链选型独立技术审稿

审稿范围：仅审报告 §2 方法与 §3 的 Q3、Q4、Q5；未审 Q1、Q2。
核对材料：报告本身、`research/r2-nautilus-source-verify.md`、
`research/r1b2-market-data-storage.md`、`research/r1-features-protocol.md`、
`research/r2-stats-verify.md`、`research/round3-findings.md`。
Nautilus 另按用户指定复核 v1.227.0 tag 的
`crates/execution/src/matching_engine/engine.rs` 与
`crates/backtest/src/exchange.rs`。

## 总裁定

Q3 的 Parquet 真身 + DuckDB 查询层可以作为 PoC 起点，但入湖闸门还不够
成为可复现数据产品。Q4 的源码事实大体正确，职责方向应为“永续语义参考
实现 + Nautilus 兼容性审计”，而不是让两个实现互相证明。Q5 的特征复现
路线可开工；EPV≥10 不能直接推出“百级正样本可用 10–30 维”，自写
PurgedKFold 也不能只靠一次对拍获得可信度。

发现分级：必修 5 条，应改 8 条，建议 6 条。

## 必修发现

### 必修-1：Q4 的“主数字来源”缺少第三方真值与不变量

定位：报告 §3 Q4 表后“自研差分模拟器（主）+ Nautilus…”，以及
`round3-findings.md` 的 Q4 裁决；PoC 清单第 5 项（约报告
`2026-09-07-quant-toolchain-selection-report.md:183-184`）。

源码结论核对结果为正确：v1.227.0 的 `SimulatedExchange` 没有
`process_mark_price`；`engine.rs` 的非 LastPrice 分支回落到 bid/ask，
bar 路径把 OHLC 展开成 TradeTick，且 L1 价格随 tick 设为
`bid=ask=last`。`exchange.rs` 也没有 funding 结算路径。该结论可由
v1.227.0 tag 的两个指定文件及 `matching_core` 的触发判断共同支持。

问题在架构推断，不在源码事实：自研实现若同时定义“主数字”、mark 触发、
funding、双界，Nautilus 只能验证其订单状态机，不能验证永续业务语义。
两个实现的成交序列一致，不代表两者都正确。

具体修法：把验收拆成三层：
1. 规则不变量测试：撮合前后数量守恒、手续费/资金费率账务守恒、
   reduce-only 不增仓、GTD/IOC 终态唯一、订单与成交可重放。
2. 独立事件模型：用手工构造的最小 episode 生成期望结果，覆盖 mark
   与 last 分离、资金费率结算边界、同 bar 双触发、跳空和部分成交。
3. Nautilus 对拍：只对订单状态、过滤器、OrderList/GTD、价格精度和
   可归属事件做差异审计；永续扩展差异必须单列，不能以“序列一致”作
   总体正确性证明。

### 必修-2：更好的第三条路应纳入候选，而不是二选一

定位：报告 §3 Q4“纯 Nautilus 壳策略”与“自研差分模拟器”比较，
以及 `round3-findings.md` Q4 裁决。

当前方案把自研与 Nautilus 都当完整回测器，维护两套撮合语义，成本和
差异解释压力都很高。更稳妥的第三条路是：共享一个项目内的
`order_plan -> canonical execution events` 领域模型，永续特有的
mark/funding/双界作为独立模块；Nautilus 只消费规范化订单与市场事件，
并通过适配器输出其 FSM 事件。这样自研不是“另一个完整撮合器”，而是
对缺失语义的参考模型与账务层。

具体修法：先冻结事件 schema、价格/数量单位、时间边界、订单优先级及
资金费率账务事件；为每个 episode 保存输入 manifest、两引擎版本、
随机种子、事件 diff 和解释码。若必须保留完整自研撮合器，也要把
“参考模型”和“生产数字引擎”分离，避免同一套 helper 同时生成答案和
生成测试期望。

### 必修-3：Q3 入湖闸门漏了可追溯性、幂等和语义质量

定位：报告 Q3“风险与反驳”段（约 `:106-108`），以及 PoC 清单第 4 项。

已有 checksum、月度 bar 数、缺口回填、时间戳单位、表头检测，方向正确，
但仍遗漏：
- checksum 文件本身的来源、下载时间、HTTP 响应和文件长度；
- ZIP 内文件名、行数、最小/最大时间、重复主键、排序和跨文件重叠；
- 永续 symbol 的上线/下线、合约迁移、交易暂停和时区边界；
- funding 的 `calc_time` 与实际结算时点、可变 `funding_interval_hours`；
- metrics 字符串时间和 mark/last 的毫秒时间统一后的舍入规则；
- 失败重试、部分下载、重跑不重复写入，以及“缺失”和“零成交量”区分；
- raw ZIP、解压 CSV、规范 Parquet 之间的 manifest 链；
- Parquet schema 演进、分区谓词、压缩 codec 和精度损失检查。

具体修法：建立每个 partition 的 immutable manifest，至少含 URL、HEAD
元数据、checksum、下载/解析器版本、行数、主键范围、重复数、缺口、
schema hash、源文件 hash 和状态。入湖采用临时目录 + 原子 rename，
同一 `(dataset,symbol,period,source_hash)` 幂等；异常只进入 quarantine，
不得静默补零。另加资金费率结算账务单测，而不是仅做 ASOF 连接单测。

### 必修-4：EPV≥10 被错误地当成维数上限

定位：报告 Q5 的“维数上限”行（约 `:149`），以及
`round3-findings.md` Q5“EPV≥10 裁到 ≤30 维”。

EPV 是特定模型、参数化和事件定义下的经验启发式，不是特征选择定律。
百级正样本时，N/10 可能只有约 10 个变量；但 Alpha158 变体有高度相关
的滚动特征、重复窗口和同一事件簇，真正有效样本量可能远小于正样本数。
反过来，正事件数也不是所有参数的唯一信息量，删掉强相关特征后可支持
的维数与简单 N/10 不等价。

具体修法：把 N/10 改成“预注册的保守起点”，并同时报告每个训练折的
有效事件数、事件簇数、重叠率、特征相关矩阵/有效秩、缺失率和标签基准
率。用训练折内嵌套选择、稳定性选择或正则化；最终维数由时间外推表现、
置信区间和敏感性分析共同决定。禁止用全样本 N 先定维数再做 CV。

### 必修-5：自写 PurgedKFold 的正确性验收不足

定位：报告 Q5 主 CV 行（约 `:152`）、PoC 清单第 7 项（约 `:185`）。

“参考 AFML + purgedcv 对拍”不是充分保证。必须明确事件标签区间
`[t0,t1]` 的端点闭开语义、训练/测试边界、同一事件簇的隔离、embargo
是按时间还是按样本、缺失 t1、排序不稳定和最后折不完整等情况。若
embargo 只“走前”但实现按行数切除，会在不规则事件和跨资产数据上漏 purge。

具体修法：先写一个枚举所有区间交集的 reference implementation，再让
优化实现对随机区间、相同时间戳、不同资产、变长标签、空折和边界点做
性质测试。对每个 split 输出 train/test 索引、被 purge 的原因和 embargo
时间范围；把 `TimeSeriesSplit(gap=)` 明确降级为定长标签基线，不能作为
事件级正确性的旁证。加入 cluster-level split，防止同一交易员/信号源/
仓位 episode 跨折泄漏。

## 应改发现

### 应改-1：Q4 “markPriceKlines 作驱动 bar”不是 mark 触发的等价实现

定位：报告 Q4 风险段与下一步（约 `:138-140`）。

mark 价格 K 线只有 mark 的 OHLC；把它喂成交易 bar 会同时改变成交价格、
盘口状态和限价成交路径，不能只替换止损触发基准。该方案可作为压力
场景或上界，不应称为近似真实 mark 触发。

修法：市场 last/quote 驱动成交，独立 mark stream 仅驱动触发器；若只有
1m mark OHLC，输出“触发可发生/不可发生”的区间而非单一成交价。

### 应改-2：funding 后算可能改变强平、保证金与资金曲线

定位：报告 Q4“funding 必须外挂/后算”及 Q3 funding 数据说明。

若资金费率只在最终 PnL 后加总，无法反映结算时点对余额、保证金、风险
限额和后续订单的影响。尤其跨结算时点持仓变化不能用区间末持仓估算。

修法：把 funding settlement 作为有序账务事件，按结算时间切分持仓，
记录费率、名义价值、支付方、收款方、余额变化，并让风险/强平逻辑消费
结算后余额。`funding_interval_hours` 只能辅助定位，仍须验证实际时间。

### 应改-3：Q3 “覆盖矩阵”没有定义通过标准

定位：报告 Q3 下一步（约 `:108`）。

44 品种 × 4 类型只证明下载任务跑过，不能证明研究所需时间范围、
连续性和跨表可连接。修法是按 symbol/contract lifecycle 输出覆盖率、
最大缺口、重复率、schema hash、mark-last 时间偏移和 funding 对齐率，
并定义失败阈值及人工豁免。

### 应改-4：DuckDB 缓存策略缺单写者与并发约束

定位：报告 Q3 入湖闸门“可随时删除重建”。

可重建不等于可并发写。修法：缓存只读视图与构建任务分离，单写者锁、
临时数据库、校验后原子替换；多进程研究只读 Parquet 或只读 cache。

### 应改-5：Alpha158 “变体”需要逐算子契约

定位：报告 Q5 特征字典（约 `:147`）。

墙钟窗口、bar VWAP、`close_time <= signal_ts` 都是合理重定义，但已经
不是 Qlib Alpha158 的可互换实现。修法：每个算子登记窗口单位、端点、
缺失填充、warm-up、分母为零、时区、输入列和与 Qlib 的差异；用合成
序列逐算子 golden tests，不能只做整体相关性。

### 应改-6：Q5 的统计评分把“高置信证据”与“高适用性”混在一处

定位：报告 §2 评分模型及 Q5 表。

置信度声明不反映吸引力是对的，但 Q5 的分数仍把成熟库、自写代码、
研究协议和统计有效性压成一个分数，读者无法看出 74 分方案的主要风险。
修法：Q5 分为特征计算、标签/CV、推断/不确定性三张能力表，并单独列
“未验证项不得给满分”的证据门槛。

### 应改-7：Q4 评分没有为组合方案明确成本归属

定位：Q4 评分表（约 `:114`）。

77.8 的加权算术本身成立，但能力、成熟度、TCO、退出成本是组合方案
的分数，纯 Nautilus 与纯自研却按单方案比较，分母不一致。修法：按
“双引擎 PoC / 单引擎长期维护”分别评分，列出维护工作量、运行资源、
升级回归和差异解释成本。

### 应改-8：PoC 缺少停止规则和样本代表性

定位：Q4 20 个 episode、Q5 N<300 规则。

20 个 episode 只能发现明显差异，不能支撑稳定性结论。修法：按订单
类型、波动状态、资金费率方向、跳空、同 bar 双触发和多账户隔离分层
抽样；预先定义差异预算、不可解释差异阈值和复现失败即阻断的规则。

## 建议发现

1. 报告 Q3 应把 bookTicker 仅自 2023-05 起的覆盖限制显式传到 post-only
   结论；没有盘口历史时不要把成交 K 线的可成交性外推为队列真实性。
2. Q3 的“DuckLake 作表级版本备选”应先做许可证、并发和恢复演练，
   不要在 Parquet manifest 尚未落地前引入第二种版本系统。
3. Q5 bootstrap 应把 event cluster、交易员/信号源、symbol 和时间依赖
   的层级关系写入协议；普通 block bootstrap 不能自动实现簇抽样。
4. Q5 应报告选择偏差：158 条表达式、18 条 Alpha101 和自建因子都要在
   预注册清单中冻结，禁止看到测试结果后删换因子。
5. imodels 版本距今较久且 API 输出未核，建议在 PoC 中锁定 API snapshot
   和最小可复现规则导出，而非把规则可解释性当作已验证能力。
6. 评分表应增加“阻断项”栏；缺少 funding 账务、事件级 purge 或数据
   manifest 时，即使总分高也不能进入下一阶段。

## 开工裁定

**Q3–Q5 选型不能按现状直接作为 PoC 开工依据；可以在补齐 5 个必修项
后开工。** 其中 Q3 存储和 Q4 Nautilus 源码判断不需要推翻，Q4 需要
重写双引擎职责与独立真值设计；Q5 必须撤销把 N/10 当硬上限的表述，并
完成 reference PurgedKFold、嵌套选择和 cluster 隔离协议。

最站不住的一个断言：**“已闭合正事件数 N/10（EPV≥10）就是特征维数
上限，百级正样本据此即可决定 Alpha158 变体维数。”** 这把经验规则
写成了可执行的硬约束，却没有有效事件数、相关性、事件簇重叠和嵌套
选择证据。
