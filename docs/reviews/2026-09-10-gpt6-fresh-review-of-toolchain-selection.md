### F02｜必修｜“主数字只能来自自研”是未经比较的架构推断

定位：§1 报告:L21；§Q4:L143–146。
源码证明默认实现有缺口，没有证明缺口必须通过第二套主执行器补齐。

同文件 :200 的 FXRolloverInterestModule 已调用 exchange.adjust_account；engine.pyx:1862–1864 会驱动模块。
这是“单个 Nautilus 执行内核 + 外部 mark 条件控制器 + 同时序 funding 模块”的实在候选接口。
它尚需验证 mark 到订单释放的事件顺序、资金入账与风控刷新顺序，不能直接宣布优胜。
修法：用同一最小 episode 集比较这个候选与自研参考执行器，记录代码量、可验证性、性能、维护面。
共享输入契约合理；共享撮合判定 helper 会制造共同错误，应只共享 schema、单位和事件封装。
若自研产出成交主数字，就必须承担挂单队列、部分成交、撤改单、组合订单及账户约束，不能只称“缺失语义层”。

### F03｜必修｜两条 OHLC 路径不构成一般收益上下界

定位：§Q4，报告:L137、L143；§5:L192。
独立反例：初始多仓 100，追踪止损距离 5；bar 为 O=100、H=110、L=90、C=100。
单调 O→H→L→C 在回落 105 出场，收益 +5；O→L→H→C 在 95 出场，收益 -5。
同样 OHLC 允许 100→110→90 的跳跃路径，stop-market 在 90 附近才能成交，收益可为 -10。
即使限定连续无滑点，多次触发、撤改、再入场也需要枚举更多状态；两条极值顺序没有普适界限证明。
mark 和 last 各自 OHLC 还允许不同的相对时间排列，不能机械配对同序价点。
修法：改称“选定路径情景区间”；只有明确连续性、成交假设和受限订单状态机并证明后才能叫上下界。
验收：将上述跳空例、同分钟两价格流异步例加入独立期望集；主结果单列不可识别订单占比。

### F04｜必修｜账户资本与 funding 精度尚不足以定义“主数字”

定位：§Q4，报告:L132、L145–148；§5:L192。
参考实现不能一处说 funding 后算，另一处又让它影响保证金与强平；两者只在排除资本约束时才可能等价。
本次 funding CSV 仅给结算时间、间隔和费率，没有精确结算 mark；一分钟 mark OHLC 不能自动补出该值。
多个计划共享账户时，逐计划独立收益相加也不能表达资金占用、净仓、风险限额及同时下单竞争。
修法：冻结事件收益估计与账户资金曲线两种 estimand；指定手续费、滑点、杠杆、仓位模式和资金不足处理。
funding 用结算前有符号仓位及结算 mark 入账；精确 mark 缺失时披露近似并做敏感性，不声称交易所精确账务。
同时间 funding／平仓／GTD 的顺序必须显式；强平所需证据不够时限制研究问题，不能默认“永不强平”。

### F05｜应改｜Nautilus 审计范围和实盘对账标准过宽

定位：§Q4，报告:L136、L144、L148。
Instrument 带 min_notional 等属性不等于所选下单通道会执行 Binance 全部 filter。
本次 matching engine 检查命中主要是 precision、price increment；仅这些证据不能认证交易所 filter 全覆盖。
真实撮合的价差、排队和延迟不会因回测模型正确就落在一 tick 内；该阈值适合确定性合成例。
修法：逐条列 PRICE_FILTER、LOT_SIZE、MARKET_LOT_SIZE、最小名义额、reduce-only、订单组合的实际执行层。
为每条规则造合法／非法各一例，验证拒绝事件；OrderList 也不能自动等同 Binance 原子 OCO。
实盘 episode 拆成确定性状态对账和执行误差分布；“差异都有解释码”之外还需不可解释误差率上限。

### F06｜应改｜数据源方向成立，覆盖论证及剔除单位须收窄

定位：§1，报告:L14、L20；§Q3:L85–97；§5:L189。
免费 last／mark／funding／OI 支撑低频 PoC 的方向成立；“唯一缺清算数据”超出证据。
精确历史 filter、资金费结算 mark、盘口执行条件也可能缺；是否必要取决于研究问题。
“某 partition 不可归因就排除 symbol”太粗，会随缺失结构改变币种和行情阶段分布。
修法：按上市／退市区间建立覆盖分母；缺失按字段和 episode 传播，保留排除理由和原始样本分母。
把“免费源够用”改成有条件结论；不要把 BTC 样包或 HTTP 200 当作全市场验收。

### F07｜必修｜入湖闸门必须覆盖 point-in-time 与缺失传播

定位：§Q3，报告:L107、L111；§5:L189。
行数、去重、schema hash 和可解释 quarantine 仍不能证明用于某信号的值当时可获得。
[DuckDB ASOF 文档](https://www.duckdb.org/docs/current/sql/query_syntax/from)允许多种不等号，每左行至多一个匹配；不替研究者验证时点和陈旧程度。
修法：每行区分 event_time、available_at、ingested_at；ASOF LEFT JOIN 保留未匹配样本并限制最大年龄。
mark/last 缺口不得无限前填；funding 的已结算值与当时预测费率分列，不得提前把最终费率当特征。
bar 收盘时间等号是否可用取决于接收延迟与消息排序，不能只用严格大于号解决。
补充闸门：UTC／时间单位、主键市场身份、OHLC 合法性、价格精度、成交量单位、排序及历史规则有效期。
质量状态必须逐列传给特征和回测；quarantine 有解释不等于准许当正常数据使用。

### F08｜应改｜Parquet + DuckDB 合理，但单文件原子 rename 不等于数据集快照

定位：§Q3，报告:L101、L107；§5:L189。
单人追加式分析无需先上常驻时序数据库；Parquet 文件与 DuckDB 查询层的退出成本较低。
问题在多个分区、修订版和特征表的共同发布：读者可能用新 last、旧 mark、另一版 funding 混算。
修法：保留 raw ZIP／checksum；每次研究固定包含所有对象哈希、schema 版本和变换版本的 dataset manifest。
先完整写好不可变分区，再切换一次 manifest 指针；DuckDB 只读 manifest 列出的文件，不扫可变 glob。
同值重复可确定性去重，冲突重复先隔离；保留所有源对象和选版规则，不能只留下最终 Parquet。
验收：故意中断多分区发布，旧快照仍可读，新快照未完成时不可见；这属于本地文件协议，无需大平台。

## 4. Q1：规模可行，真正风险是历史可见性

[Telegram 官方导出介绍](https://telegram.org/blog/export-and-more)明确支持 JSON、图片及大量消息，数万条不是明显超出能力的规模。
[Telethon iter_messages 文档](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.messages.MessageMethods.iter_messages)支持历史遍历、offset 和等待参数；没有为本项目提供限流 SLA。
据此接受 TDesktop 一次性快照 + Telethon 对照增量作为 PoC 组合，但不能承诺全量、耗时或中断自动续传。

### F09｜应改｜冻结不等于立即使账号和 session 全部作废

定位：§1，报告:L22；§Q1:L53、L60。
[Telegram 官方授权协议](https://core.telegram.org/api/auth)描述冻结账号为只读，并按方法及 peer 返回不同错误，之后可能删除。
这直接反驳“冻结 = 账号连同 session 作废”的无条件表述；报告引用的 tginfo 也不是官方协议。
修法：区分受限、冻结、auth key 失效和账号删除；记录服务端错误与申诉／删除期限。
冻结后停止补拉是可以保留的保守政策，但同账号 Desktop 导出也可能受限，不能承诺切客户端即可恢复。

### F10｜必修｜最终编辑版不能回填成原始可交易信号

定位：§Q1，报告:L56、L60；§Q2:L81；§Q5:L155。
历史当前版本加 edit_date 不能重建编辑前入场价、止损或止盈；截图也可能是事后战报。
即使所有行情都严格 as-of，拿修改后的信号在原消息时间回测仍有未来信息。
修法：保留 message_date、edit_date、snapshot_at、首次实收时间及内容哈希，建立版本来源。
未知原始内容的消息可用于结构研究；交易收益研究只允许从可证明的可用版本时间开始，或作为不确定样本单列。
删除的失败信号不能由“现存历史一致”消除幸存偏差；报告要限定推论总体为可观察消息，并另建前瞻样本。

### F11｜必修｜双客户端一致不证明全量，缺失不能直接消失

定位：§Q1，报告:L60；§5:L187–188。
同样权限不足、管理员删帖、加入前历史不可见会让两个客户端共同缺失，Jaccard 仍可能为 1。
次号与主号可见范围不同；跨时导出期间的新帖／编辑又会产生正常差集。
修法：每频道冻结观测时间窗和高水位 message_id，登记账号权限、最早可见日期、过滤设置及导出起止时间。
统一 Desktop／Telethon 的 peer 类型、ID 编码及迁移映射；username 和消息 ID 单独都不能作为跨频道稳定主键。
媒体核验另设内容 hash、类型、尺寸、下载状态；不是每消息都应有一个媒体文件，相册和多图须正确归组。
不可恢复图片、空文、服务消息和非信号也保留在清单中，说明从消息→候选→计划的每一步损耗。
断点恢复、重拉最近窗口、编辑／删除增量及媒体 file reference 过期重取均列为 PoC 项，不能假定已实现。

## 5. Q2：抽取辅助可用，统计验收与锁箱需补齐

### F12｜必修｜校验路径相关性不是自动采纳阈值

定位：§Q2，报告:L76、L81；§5:L190。
解析器与 LLM 共错率没有显著高于独立假设，并不表示绝对错误率足够低；百级样本还容易检验功效不足。
分歧交第二家 LLM 不能自动变成人工真值；字段各自高准确率也不保证一整张 order_plan 正确。
修法：预注册整单关键字段错误率、数字级容差、漏检信号率和拒答率；按频道／图文类型／模板分层抽审。
价格、方向、数量、品种映射等关键项以人工金标验收，困难样本进入人工最终确认或明确拒收。
独立二项抽样下，0/100 错的双侧 95% Wilson 上界约 3.70%；0/50 约 7.13%，不是接近零的保证。
若要零错误样本下该上界低于 1%，约需 381 个独立样本；图或消息簇相关时还须调整，不可把字段当独立样本。
30% 图片纠错率只能作为人工工作量止损线；应另定准入后的错误率目标和收益对标签错误的敏感性。

### F13｜必修｜哈希锁箱不是盲评锁箱，预测隐藏也不足以防结果污染

定位：§Q2，报告:L81；§Q5:L159；§5:L191。
[OpenTimestamps](https://opentimestamps.org/)提供存在性时间证明；它不证明内容正确、首次创建时间、作者身份或研究者没看过测试结果。
git 可重写，manifest 可重新生成；仅校验文件完整性也不证明最终测试集没被反复开箱。
修法：将抽取金标、开发标签和最终检验集合分开；按时间及 episode 先分配，再将最终集合限制给评估入口。
确认界面除隐藏模型预测，还要隐藏后续走势、战报、未来回复；原始材料固有事后信息单独标识。
预注册主指标、排除规则、成本、路径情景、尝试预算和停止条件；每次开箱登记请求与不可变结果。
锁定 dataset／prompt／模型版本／schema／人工修订／代码环境哈希；重建数据与严格复现非确定性 LLM 输出是两回事。

### F14｜应改｜Batch 与确认工具的工程成本被低估

定位：§Q2，报告:L73–75、L81；§5:L190–191。
[Label Studio 预标注说明](https://labelstud.io/guide/predictions)支持导入预测；它不证明本项目动态 TP 表单及导出回写已可用。
修法：任务使用稳定 ID 和 schema_version；预测、人工批准版、修订记录分存，重试不得覆盖已批准标签。
Batch 结果按自有 ID 关联，处理乱序、重复、部分失败；原图 hash、OCR 坐标、文本 span 和上下文边界需落库。
数字使用 Decimal／定点及显式单位；验证多 TP 数量、百分比分配、方向与价位关系；不明确时拒答。
Repeater 的变长档位、删除／重排、零档、复杂回复和备份恢复均需实际导出再导入，本次没有确认其通过。
三小时人工预算若含金标、纠错和复审，应以每类任务实测中位／P90 用时外推。

### F15｜建议｜预算用真实 token 与人工分钟复算

定位：§Q2，报告:L75；§5:L190。
本次[Claude 价格页](https://claude.com/pricing)可见 Sonnet 5 的 2/10 美元每百万 token；[Gemini 价格页](https://ai.google.dev/gemini-api/docs/pricing)也支持所述促销及 Batch 档位。
价格方向不构成本次否决项，但“5000 条双模型低于 30 美元”缺 token 分布、图片比例、重试和裁决次数。
修法：抽样 100 条统计输入／输出／思考 token、媒体大小、每条调用次数及人工时间，给 P50/P95 总成本。
模型选择先按关键字段金标表现，再看 API 费用；不能用别的任务上的共错比例替代本任务测量。

## 6. Q5：先明确估计对象，再谈特征与统计工具

### F16｜必修｜“百级正样本”尚未定义，N/10 不能承担模型预算

定位：§2，报告:L33；§Q5:L157；§5:L193。
如果“正事件”指盈利交易，只数胜者会遗漏负类、未成交、到期和删帖；如果指有效信号，就不等于 logistic 的 outcome events。
[van Smeden 等原论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC5122171/)不支持将十事件规则视为通用正确性保证。
从 158 个特征筛出 10 个，搜索自由度并不等于 10；有效秩小也不能消除阈值、窗口和规则搜索的过拟合。
修法：先定义所有候选计划、入选／未成交／亏损／盈利／删失的分母，分别报告样本数、结果事件数和独立簇数。
首轮只做预先指定的少量可解释特征及固定规则基线；以折内样本预算决定是否训练，不强制“必须找出策略”。
禁止只按最后闭合者分析固定结束日附近信号；预设统一观察期，或显式处理右删失。

### F17｜必修｜PurgedKFold + “embargo 走前”没有定义部署场景

定位：§Q5，报告:L160；§5:L194。
一般 purged K-fold 允许测试块之后的样本进入训练；去除标签重叠不等于只使用部署时已经发生的数据。
embargo 放在测试块之前还是之后应由信息区间决定，不能只写“走前”；[sklearn CV 文档](https://scikit-learn.org/stable/modules/cross_validation.html)也区分时间与分组验证目标。
修法：未来交易表现的主评估使用 expanding／rolling walk-forward，只训练测试起点前可用且标签已完成的样本。
显式给出标签区间、特征可用时间及 overlap 谓词；闭区间相交为 max(start)≤min(end)，半开区间改为 <。
保留双向 purged CV 只能回答另一种稳定性问题；不得把该数值直接叫上线后的预测表现。
按 episode／复制信号隔离用于防重复；留交易员／频道验证用于新来源泛化，两者不能一律合并。
五个频道若整频道隔离只剩极少组；全时域重叠图还可能连成一大簇，须报告可用训练集而非强行折分。
所有插补、归一化、筛特征及超参搜索只在内层训练完成，空折、单类折应明确拒绝评估。

### F18｜必修｜簇 bootstrap 与 LLM 反复试验尚无完整推断协议

定位：§Q5，报告:L161、L163；§5:L194。
[arch 官方文档](https://bashtage.github.io/arch/bootstrap/timeseries-bootstraps.html)提供序列 block bootstrap，不能替使用者决定不规则 episode 的重采样总体。
同日跨币、跨频道信号共享市场冲击；只按单个 episode 抽样会低估不确定性，只按频道又可能只有五簇。
修法：明确估计的是固定策略的事件平均收益还是资金曲线统计；对跨资产采用共同日历块，保留块内关联。
事件模型的替代方案为明确的簇抽样；报告簇数、块长、块长敏感性和不可稳定估计的情况。
比较两策略应配对重采样；若要估计整个选模流程的误差，则每次重采样须重跑选择，不能只抽最终赢家。
LLM 每个假设、窗口、成本和筛选尝试均记账；预留一次最终时序测试，外层结果反馈给 LLM 后不再是外层。
[DSR 原论文](https://ssrn.com/abstract=2460551)说明选择偏差与多重尝试会夸大表现；不要求百样本强上 DSR，但必须控制尝试预算及完整披露失败试验。
禁止把不等间隔交易收益直接按固定 bar 频率年化 Sharpe；先形成定义清楚的日历资金序列或报告事件级指标。

### F19｜应改｜Alpha158 变体是新的特征实现，不应靠名称背书

定位：§Q5，报告:L155–158；§5:L193。
[Qlib loader 源码](https://github.com/microsoft/qlib/blob/main/qlib/contrib/data/loader.py)可支持表达式核对；变更窗口单位与 VWAP 后不能继承原特征的实证有效性。
修法：固定所参考源码 commit，逐算子约定 ddof、rank／并列、零分母、缺失传播、最少观测数和时区。
墙钟窗口遇到缺 bar 与“最近 N 行”不同；EMA／Wilder 等递归指标也须有一致的预热和状态延续。
VWAP 用正确的 quote/base 成交量口径；mark/index CSV 的零量列不是可交易成交量，不能混入价量因子。
截断重算要保留相同前历史／状态；NaN 注入应只改变未来片段，另测补洞、变更发布时点和多资产拼接。
建议先实现 5–10 个预指定算子，再按真实需求扩展，不把完整复刻 158 维作为数据 PoC 前置条件。

修法：导入器只读源数据，抽取输出须 schema 校验，人工批准后才可生成研究计划；记录审批版本和身份。
对账使用只读导出；研究结果进入生产前另走发布流程，不能将研究批准当成生产 order_plan 授权。

修法：先一天级源码／事件顺序 spike，再最小订单子集，再多档 TP 和并发账户；每阶段给通过条件后重新估时。
性能用真实品种数、分钟数、计划重叠度、峰值内存和重跑时间实测；不要仅以“单 engine 长跑”保证可行。

## 8. PoC 开工裁定与前提

裁定：有条件允许“验证型 PoC”；不允许将报告现有架构与得分视为已经验收的技术决策。
可以立即开始：单频道离线快照对齐、BTC 与目标币归档质量扫描、盲金标表单样例、少量手工订单语义例。
前提一：开工任务书先采用本审查中的受限范围，不承诺全量历史、收益上下界或主数字正确性。
前提二：引擎定型前关闭 F02、F03、F04，并验证实际 Python 路径及订单规则；不以静态源码代替运行验收。
前提三：历史收益研究前关闭 F07、F10–F13，给出可交易版本与可观察总体，接受不可识别样本无法补救。
前提四：训练和统计结论前关闭 F16–F18，冻结 estimand、时间外验证、尝试预算和最终开箱规则。
前提五：最终工具采购／定型前关闭 F20，重算全部得分并补 Q5 的输入；新评分未必改变前三类工具方向。
12 项必修：F02、F03、F04、F07、F10、F11、F12、F13、F16、F17、F18、F20。
最站不住的断言：§1:L21“主数字只能来自自研参考模型”；已见源码扩展接口，默认功能缺失不足以推出唯一架构。
本裁定不批准生产部署、RESUME、真实交易或对任何手动订单的操作。
