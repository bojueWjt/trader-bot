# NautilusTrader/Binance Futures Compatibility Report

Window B / B-00 spike for NautilusTrader `1.227.0` and Binance USDT-M Futures.

This report separates local static checks from target-host empirical evidence.
pudu-mini has no Docker and uses Python 3.14, so Nautilus runtime evidence must be
collected on a Linux + Docker + Python 3.12 host.

## Local Static Verification

To run on pudu-mini:

```bash
python3 -m py_compile services/nautilus-node/spike/*.py tests/nautilus/spike/*.py
bash -n services/nautilus-node/spike/run_spike.sh
```

Expected: both commands exit `0`. Docker build is intentionally skipped locally.

## Unsupported Items And Alternatives

| Item | Current Status | Alternative / Mitigation |
|---|---|---|
| Nautilus runtime on pudu-mini | Unsupported | Run all Nautilus import/runtime checks in the target Python 3.12 container. |
| Binance live endpoints | Intentionally unsupported in B-00 | Use only USDT-M Futures testnet credentials and endpoint guards. Live enablement is a later gated window. |
| Order/cancel smoke evidence | Pending target-host API completion | `testnet_smoke.py` returns non-zero with credentials until a real Nautilus 1.227.0 order -> cancel path is verified. Do not mark B-00 done without that log. |
| Conditional/stop order evidence | Pending target-host API completion | Capability matrix lists core enum/config support; use testnet smoke evidence before strategy implementation relies on it. |
| reduce_only evidence | Pending introspection/runtime confirmation | Until verified, strategy work should reconcile positions after fills and avoid assuming adapter support. |
| Instrument precision | Pending loaded-instrument evidence | Round from Nautilus loaded Instrument fields in runtime code; never hard-code Binance symbol precision. |
