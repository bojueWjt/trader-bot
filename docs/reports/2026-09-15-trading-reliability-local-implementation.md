# 交易稳定性修复：本地实现与验收

这是 2026-09-15 根因方案的实现记录，优先级为交易稳定性。用户要求改由 Codex 直接修复；先前工作已提交为 `4aceb0f`、`7548d56`、`cbb56e9`。本记录不将代码提交或本地测试视为线上生效。

## 修复范围

- 仓库 dashboard 持仓操作原先把平仓请求发送到不匹配的 `close_all` 命令接口。现有平仓、部分平仓、移止损界面改用正常 operator orders 接口，携带真实账户、方向与持仓引用。提交前保存完整请求和稳定编号，超时后保留身份并查询原操作；明确区分受理、提交、部分成交、成交、拒绝和待核对。用户手机实际客户端尚未确认。
- 交互 Hermes 仍有全局查询与操作能力。signal 凭证由服务端绑定账户，不能伪造人工授权，也不能读取其他账户状态；主体写入审计及操作计划。凭证碰撞拒绝认证。
- signal claim、不可变请求、操作绑定和任务完成通过现有 Postgres 事务接入正常风控/交易入口。重试沿用同一业务身份；HTTP 结果不明先核对，租约过期但没有已受理操作时释放账户队列；拒绝原因保留并脱敏。编辑链任一旧版本已有操作时，后续风险增加必须先核对，不能通过多次编辑绕过。
- 仓位语义版本独立于数量，平仓与 CLOSE_ALL 增加版本。迟到加仓在控制面及节点提交前核验版本；相同数量、相同持仓 ID 的平仓重开不能把旧分析变成新授权。节点持久化失败时关闭提交路径。
- feeder 保持一个 Telegram 入口。默认旧 writer 加 shadow；显式开启某账户后，只接受持久高水位之后、接收时间门槛之后的新消息。旧任务、旧 shadow 与历史信号不会自动提升为可交易任务；撤销配置保持冻结，不静默回到旧 writer。
- OLM 移除了 pfill/recon/价格接近等唤醒 Hermes 的交易路径，以及凭挂单列表缺失就把投影改成撤销的逻辑。只保留确定性健康检查和去重通知；严格识别机器人订单，手动单不撤、不骚扰。
- v3_query/v3_trade 改走控制面；不依赖宿主数据库、docker.sock 或生产 env 文件。不再把明确的 open 静默改写为 add。
- 机器人入场单与平仓冲突时，先确认撤单，再取得新仓位证据并重走现有 planner；未知取消、证据过时或 cache 未收敛保持待核对。平仓实际终结证据写入既有 inbox，重启保留，完整成交后允许新的合法操作。
- 空/不足/EXTERNAL hedge cache 的内部 reduce-only 适配统一在既有提交入口检查交易所证据、授权 book 和数量。正确 LONG/SHORT 提交 ID 保留；缺证据不能无条件绕过 RiskEngine。
- algo 路由原本已区分，本次修正的是终态语义：明确 CANCELED 幂等成功；NEW/UNKNOWN/TRIGGERED 等不能冒充撤单或成交。门禁复用同 CID、同 symbol 的新鲜完整保护单证据，薄投影不会再次否定它。
- 订单投影只保留 OrderProjectionReducer 写入路径。从既有 execution_events 累计原生 last_qty、按交易所 trade_id 去重，迟到成交不因撤单终态被丢掉，同时间累计回报不双算，均价不被旧事件覆盖。删除无调用的另一个投影写入方法及旧派生助手。

权威事实是经过新鲜度、完整性与归属核验的交易所订单、成交和仓位；cache 和投影是派生视图。交易意图统一走现有控制面，再交到账户唯一执行器；新 `/telegram/raw/signal` 只是同一 ingress 的版本安全接入路径，避免旧服务忽略 signal 字段，并非第二条交易写入旁路。

## 生效与边界

交付核查发现两项会使业务修复无法生效的遗漏，已在本地沿原发布入口补齐：

- 原发布清单只到迁移 0018，未安装新控制面、ingress、worker 等依赖。打包、manifest、迁移与部署映射需共同覆盖 0019→0021；必须从提交对象构建，不能拿工作区文件或容器内临时热补丁代替。
- 原发布入口也未包含 dashboard。新交付将固定提交的前端构建配置、源码与资源哈希纳入同一包，安装到已核实的 `/srv/trader-v3/dashboard/dist`，保留旧目录回滚并读取真实页面与资源校验。

G0 只读复核已加载的 Caddy 配置：网页 `/v1/*` 无条件使用 `SYSTEM_OBSERVER_TOKEN` 转发，覆盖浏览器登录凭证。因此按钮即使改为正确交易接口，也会被降为只读角色拒绝。既有 `/m/v1/operator/orders` 路由保留请求凭证；补齐方案使用它，并由控制面同一 principal 入口校验现有登录服务签发的 JWT，保留用户身份。未向浏览器暴露管理员静态 token，不新增 BFF 或交易旁路。用户的手机是否实际使用该网页仍未确认。

交互 Hermes 主进程也未配置新 CLI 所需的操作凭证。部署须把现有操作凭证显式注入专用环境文件；不能仅删除旧脚本读宿主文件的逻辑后直接重启。以上接线测试及最终固定提交发布物校验独立于前述业务测试，不能跳过。

本次没有向线上部署、重启或 RESUME。本地实现不能证明用户当时手机点击已被修复，也不能证明现役 commit 已变化。正式切换须按 [切换清单](../operations/trading-reliability-cutover.md) 先完成门禁、确认旧 writer 无未知在途、再单账户移交执行权，并核对真实进程、镜像及心跳 release_id。

独立 signal worker 使用账户 OS 用户、环境与 profile 标识，并且没有 Telegram token；真实模型调用走现有 Hermes HTTP 客户端。仅设 HERMES_HOME 或 Docker sandbox 不能证明队列与权限已隔离。

本次没有新增自动 GTC 48 小时撤单/续单、自动 TP 后移保本等策略；无法从语义结构得到确定数量或成本的动作明确拒绝。删除旧 LLM 生命周期流程不代表这些策略已自动迁移完成。

版本校验以控制面下发的版本及节点本地持久版本为依据；它不是节点每次下单前同步读取控制面。未送达节点的远程命令不能被描述为已在节点生效。
